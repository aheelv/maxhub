# 《人工智能工具应用实践》

## 第 2 章　大语言模型：从 n-gram 到 Transformer 与推理模型

> **所属模块：**模块一 · AI 基础与背景　|　**学时：**2 课时（讲授 45 分钟 / 实践 45 分钟）　|　**课程主线定位：**把「模型怎么工作」换算成「我怎么估算成本、怎么判断结果可信」——工具使用的第一笔账

### 一、本章定位与主线

本章仍属「认知与原理」模块，但落点从「理解架构」调整为「会算账、会设边界」。对经管类学生而言，Token 与上下文窗口不是实现细节，而是使用成本、任务拆分方式与结果可靠性的直接决定因素。章题、模块与学时不变，本次把导入与案例统一到「一次真实任务要花多少、能信多少」这一主线上。

### 二、导入

承接上一章：学生已决定用 AI 工作台整理社团材料，并把一学期的通知与单据放进同一个任务。第一次运行很顺畅，第二次开始，工具开始「忘记」前面几轮的要求；月底查看用量，发现一次看似简单的整理消耗远超预期。问题不在工具坏了，而在两件事没算清：每轮对话实际带进了多少文本（Token），以及长任务里哪些内容被截断、哪些被重复计费。

本章从 n-gram 的概率思路讲到 Transformer 的自注意力机制，但每一处技术点都对应一个使用决策：为什么要精简上下文、为什么长文档要分段、为什么「能一次跑完」不等于「一次跑对」。课程主线在此从「认识工具」推进到「带着成本意识使用工具」。

### 三、学习目标与可检验能力

本章服务于「快速掌握并熟练使用最新 AI 工具、独立解决多类真实问题」的课程总目标，学完应能：

1. 用自己的话说明 n-gram、词向量、循环神经网络、Transformer 与自注意力机制的演进逻辑，并指出每一步解决了什么使用层面的限制；
2. 区分预训练、微调与人类反馈强化学习三个阶段，说明它们分别影响输出的知识范围、任务适配与表达规范；
3. 把 Token 与上下文窗口换算为一次任务的可估算成本，能针对给定资料规模选择「精简上下文／分段／结构化输出」策略；
4. 读懂公开评测中的能力数据（如 SWE-bench Verified 一年内由 60% 升至近 100%、短任务与长任务的落差），说明其对任务拆分的启示；
5. 独立设计一次带预算上限的实测，记录输入／输出 Token 估算与结果复核过程。

### 四、核心知识点与知识递进

1. 从 n-gram 到词向量与循环神经网络：概率预测下一个词的基本思路，以及长距离依赖与顺序计算的局限；
2. Transformer 与自注意力：并行处理与「关注上下文中相关部分」的机制，2017 年原始论文《Attention Is All You Need》为可核验出处；
3. 预训练 → 微调 → 对齐（人类反馈强化学习）三阶段，以及推理模型与思维链带来的额外计算开销；
4. Token 与上下文窗口：分词不等于字数、上下文包含系统提示与历史、输出同样计费；
5. 脚手架成本：智能体运行时的默认系统提示、工具定义与仓库规则同样占用输入 Token；
6. 长任务可靠性：短时任务接近专家水平，长时任务明显落后，故须拆分、设检查点、留可复核轨迹。

### 五、最新 AI 技术跟进

以下条目为本次修订纳入的技术更新，均给出可核验出处；标注「待补充」者不写入结论。

1. **编程能力一年内快速上升**：Stanford HAI《2026 AI Index Report》官方页 Takeaway 1 载明，在关键编程基准 SWE-bench Verified 上，表现由 60% 升至接近 100%（https://hai.stanford.edu/ai-index/2026-ai-index-report，图 S18）。这解释了为何「让模型写代码完成任务」在一年内成为可用工作方式。
2. **能力上升不等于长任务可靠**：课程课件第 2 章「真实案例与数据 4/4」引用 METR（2025）与斯坦福 RE-Bench：AI 在约 2 小时的短任务上接近人类专家，在约 32 小时的长任务上明显落后；该出处同时见于课程案例页案例 03。对应本章「拆分长任务」的操作结论。
3. **脚手架本身有固定成本**：课程课件第 13 章引用 DeepSeek Harness 公开文档（developer preview）说明，默认系统提示、工具 schema、仓库规则与技能摘要都会占用输入 Token；官方仓库与文档为可核验来源，具体数值以官方文档当前版本为准，教材不独立确认任何未核验分数。
4. **模型与运行环境可解耦**：DeepSeek 官方站点（图 S23）与课程第 13 章「四种预设」内容说明，同一模型在不同 Harness 预设下表现与成本不同；这是第 12—14 章的伏笔。
5. **成本口径须按官方定价复核**：课程课件引用 DeepSeek 官方 API 定价公告（2026-08-16 起生效）。教材要求学生以查询当日的官方定价页为准重新核算，不沿用课件中的历史单价。

### 七、真实案例（背景 · 适用知识点 · 来源 · 实践任务）

#### 案例 2-1　编程基准一年内由 60% 升至接近 100%　`A 类 · 可核验真实数据`

- **案例背景：**Stanford HAI《2026 AI Index Report》官方页 Top Takeaway 1 载明：产业界 2025 年产出的著名前沿模型占比超过 90%，多个模型在博士级科学问答、多模态推理与竞赛数学上达到或超过人类基线；关键编程基准 SWE-bench Verified 一年内由 60% 升至接近 100%。同页 Takeaway 2 说明中美模型性能差距已显著缩小。
- **适用知识点：**能力演进速度、推理模型、模型与编排分工、权威数据读法
- **来源／使用场景：**https://hai.stanford.edu/ai-index/2026-ai-index-report（官方页 Takeaway 1/2，图 S18、S19）；课件第 2 章「真实案例与数据 1/4」引用同源数据。
- **面向真实问题的实践任务：**从官方页核对 SWE-bench Verified 的表述，说明「基准成绩提升」为什么不能直接等同于「我的表格任务一定能做对」，并列出三项仍需人工复核的环节。

#### 案例 2-2　短任务接近专家，长任务明显落后　`A 类 · 可核验真实数据`

- **案例背景：**课程课件第 2 章「真实案例与数据 4/4」与第 6 章「边界与风险 3/3」引用 METR（2025）与斯坦福 RE-Bench：AI 在约 2 小时短任务上接近人类专家，但在约 32 小时长任务上明显落后；课程案例页案例 03「工具不难，口径与流程才难」并列 MIT NANDA、McKinsey 与 METR 三条企业级证据。

### 八、本章实践任务（面向真实问题）

**任务名称：**第 2 次课｜把上下文换算成钱：Token 实测与成本估算

**真实问题情境：**社团资料整理任务在实际使用中出现了「忘记前文」与「用量超预期」两个现象。你需要给出一份可复核的成本估算与上下文精简方案，而不是笼统地建议「少放点资料」。

**建议时长：**70 分钟（与课程网站已发布的第 2 次课练习资源包一致，≥60 分钟）　|　**完成方式：**单人独立完成，以 WorkBuddy 为主要工具

**主要工具：**WorkBuddy（长文本处理、结构化输出、独立新会话复核）；浏览器查询官方定价页与报告原文

**操作步骤：**

1. 读取资源包中的 `reader_notes.txt`（60 条阅读记录，明确标注为虚构教学数据），按规则统计重复 3 条、空值 2 条、有效唯一 55 条。
2. 在浏览器中打开所用模型的官方 API 定价页，记录查询日期、生效版本与计量单位，填入成本估算模板；不得直接沿用课件中的历史单价。
3. 用 WorkBuddy 分别按「模糊检索四轮」与「结构化一轮」两种策略处理同一批资料，记录各自的输入／输出 Token 估算与耗时。
4. 比较两种策略的成本与结果完整度，写出取舍理由；用独立新会话复核估算式是否存在重复计费或漏算脚手架。
5. 把长任务拆为不超过 5 个子步骤，为每步写出可验证的中间产物与回滚点。
6. 填写个人验收表并导出成果；教师核验卡中的固定数值仅供教师批阅。

**成果要求：**

- 《Token 与成本估算表》（含单价来源、查询日期、两种策略对比）
- 《上下文精简方案》（说明哪些内容不再重复带入、如何分段与结构化）
- 《长任务拆分与检查点清单》（含回滚点）
- 独立新会话复核记录与本人签核说明、个人验收表

**配套资源：**课程网站第 2 次课资源包（https://aheelv.github.io/exercises.html）：任务单、`reader_notes.txt`、成本估算模板、教师核验卡等。

### 十一、本章小结

本章把模型原理翻译成两条使用纪律：一是上下文与脚手架都要计入成本，长任务必须拆分并留检查点；二是能力上升与长任务可靠性之间不能划等号。下一章进入生成式 AI 与多模态，重点从「会不会算」转为「能不能信」。
