# 《人工智能工具应用实践》

## 第 8 章　从工具到智能体：Agent 原理与 MCP 协议

> **所属模块：**模块三 · 智能体（Agent）技术　|　**学时：**2 课时（讲授 45 分钟 / 实践 45 分钟）　|　**课程主线定位：**以智能体集成平台为核心：从「我操作工具」到「我定义任务、平台编排工具」

### 一、本章定位与主线

本章是模块三开篇，也是全书纳入「以智能体集成平台为代表的最新 AI 应用」的关键章节。前三章学生已能独立交付文档、表格与分析报告；本章开始把这些步骤交给平台去规划与执行。章题、模块与学时不变，本次重点补入 2026-07-28 版 MCP 官方规范与扩展机制，并把导入、案例与实践任务统一到「定义任务与划定边界」这一主线上。

### 二、导入

同样一句「查一查上个月华东区的销量并写成一页说明」，2022 年的对话模型只能给出一套分析思路；现在的智能体集成平台可以自己打开表格、执行汇总、调用外部数据源，再把结果写成一页说明并附上来源。差别不在模型更会说话，而在于它能否调用工具、把多个步骤串成闭环，并在关键动作前征得你的同意。

MCP 官方规范 2026-07-28 版把这套连接能力写成了开放协议：服务端提供 Resources、Prompts、Tools 三类能力，客户端可发起 Elicitation，请求是无状态、自包含的，并在每次请求时协商能力；规范同时明确「用户同意与控制、数据隐私、工具安全」三项原则。本章据此把课程主线推进到一次角色转变：学生从「操作者」变为「任务定义者 + 边界设定者 + 结果验收者」。

### 三、学习目标与可检验能力

本章服务于「快速掌握并熟练使用最新 AI 工具、独立解决多类真实问题」的课程总目标，学完应能：

1. 说明智能体四要素与「感知—规划—行动—反思」循环，能指出一段执行轨迹中各阶段对应的动作；
2. 区分工具调用与函数调用，说明为何「能调用工具」是从对话工具走向智能体的分界；
3. 读懂 MCP 2026-07-28 官方规范的核心约定：无状态自包含请求、逐请求能力协商、Resources / Prompts / Tools / Elicitation，以及三项安全原则；
4. 以 WorkBuddy 为例说明智能体集成平台的扩展机制（资料库、连接器、技能、专家、自动化、发布等），并能按任务选择合适的扩展；
5. 独立完成一次端到端智能体任务，拆开执行轨迹、识别越界动作，并写出权限与边界说明。

### 四、核心知识点与知识递进

1. 智能体四要素：模型、工具、记忆／上下文、循环控制；与「生成式 AI」不属于同一维度；
2. 感知—规划—行动—反思（ReAct 类）循环，以及何时该终止、何时该请求人工确认；
3. 工具调用与函数调用：模型输出结构化调用意图，由运行时执行并把结果回灌上下文；
4. MCP 的定位：为 LLM 应用与外部数据源／工具提供标准化连接，采用 JSON-RPC 2.0，角色分 Host / Client / Server；
5. MCP 2026-07-28 规范要点：无状态自包含请求、逐请求能力协商、三类服务端能力与客户端 Elicitation、可选扩展；
6. MCP 安全原则：用户明确同意并理解数据访问与操作、数据隐私、工具代表任意代码执行须审慎；
7. 智能体集成平台实例：WorkBuddy 的资料库、自动化、发布、工作界面与六项核心能力；
8. 能力边界：短任务强、长任务弱；OSWorld 由 12% 升至约 66% 但仍约每三次失败一次。

### 五、最新 AI 技术跟进

以下条目为本次修订纳入的技术更新，均给出可核验出处；标注「待补充」者不写入结论。

1. **MCP 2026-07-28 官方规范（本次核验）**：规范页标注版本 `Version 2026-07-28 (latest)`，明确「Stateless, self-contained requests（无状态、自包含请求）」与「Per-request capability negotiation（逐请求能力协商）」；服务端提供 Resources / Prompts / Tools，客户端可提供 Elicitation；并列出「用户同意与控制、数据隐私、工具安全」三项安全原则（https://modelcontextprotocol.io/specification/2026-07-28，图 S16）。教材只采用规范原文表述，不扩展到未经核验的实现细节。
2. **MCP 扩展机制（最新）**：官方扩展总览列出 Tasks（长任务异步执行、轮询与持久句柄）、Skills over MCP（面向智能体工作流的结构化指令）、MCP Apps（会话内交互式 UI）等可选扩展，均为 opt-in 且须双方显式支持并在初始化时协商（https://modelcontextprotocol.io/extensions/overview，图 S17）。这直接支撑第 11 章多智能体与长任务编排。
3. **MCP 生态定位**：MCP 官方站点（图 S15）把协议定义为「在 LLM 应用与外部数据源和工具之间实现无缝集成的开放协议」，并说明其借鉴 Language Server Protocol 的思路；教材以此说明「连接标准化」的价值。
4. **智能体集成平台的官方定义**：WorkBuddy 官方帮助文档《WorkBuddy 简介》列明自然语言交互、自主规划与执行、多模态任务处理、本地文件操作、多任务并行、结果交付与验收六项核心能力（https://www.workbuddy.cn/docs/workbuddy/Overview，图 S14）；课程案例页案例 04 以「一个可以照着做的全场景 AI 工作台」整理该案例。图 S13 为产品官网首页真实截图。
5. **能力边界的权威数据**：Stanford HAI《2026 AI Index Report》官方页 Takeaway 4 载明智能体在 OSWorld 上由 12% 升至约 66%，但在结构化基准上仍约每三次失败一次（https://hai.stanford.edu/ai-index/2026-ai-index-report，图 S19）；这解释了为何本章强调权限、轨迹与人工确认。
6. **采用预测的规范用法**：Gartner 新闻稿（2025-08-26）为课件第 8 章与课程案例页案例 07 的出处；教材只引用其「预测性数据须写清前提与年份」的方法论，不转述未经核验的比例。

#### 案例 8-1　MCP 2026-07-28 规范：无状态核心与三项安全原则　`A 类 · 可核验官方规范`

- **案例背景：**MCP 官方规范页标注当前版本 2026-07-28，明确基础协议采用 JSON-RPC 2.0、无状态自包含请求与逐请求能力协商；服务端可提供 Resources（上下文与数据）、Prompts（模板化消息与工作流）、Tools（供模型执行的函数），客户端可提供 Elicitation（服务端向用户请求补充信息）；安全章节要求用户对数据访问与操作明确同意并保持控制、保护数据隐私、把工具视为任意代码执行并在调用前取得同意。
- **适用知识点：**工具调用标准化、Host/Client/Server、用户同意与控制、能力协商

### 八、本章实践任务（面向真实问题）

**任务名称：**第 8 次课｜跑通一次端到端智能体，并拆开它的执行轨迹

**真实问题情境：**你需要让智能体集成平台独立完成一次「读取资料 → 汇总 → 生成说明」的端到端任务，同时保证：关键动作前有确认、轨迹可逐步追查、越界动作能被识别并拦截，最终由你本人验收结果。

**建议时长：**80 分钟（与课程网站已发布的第 8 次课练习资源包一致，≥60 分钟）　|　**完成方式：**单人独立完成，以 WorkBuddy 为主要工具；对照实验与审校均用独立新会话实现

**主要工具：**WorkBuddy（任务创建、本地文件操作、资料库／连接器等扩展、执行轨迹查看、独立新会话）；浏览器核对 MCP 官方规范与平台官方文档

**操作步骤：**

1. 在浏览器中打开 MCP 2026-07-28 官方规范页（图 S16），摘录三项安全原则，写成《权限与同意清单》。
2. 新建任务工作区，读取第 8 次课资源包中的虚构素材；明确「可做 / 需确认 / 禁止」三类动作并写入任务约束。
3. 让平台自主规划并执行端到端任务，保存执行轨迹；逐步骤标注感知—规划—行动—反思四阶段。
4. 读取 `agent_trace.csv`（10 步虚构轨迹，第 07 步为越界写入尝试），指出越界动作、应在哪一步触发人工确认，写出拦截规则；不得把该轨迹说成真实产品日志。
5. 做对照实验：同一任务分别用「纯对话」与「带工具／连接器的智能体」完成，比较两者在可追溯性、结果完整度与所需人工确认上的差别。
6. 按官方六项核心能力逐项核对实操中确实用到的能力；另开独立新会话以审校员视角检查权限清单与轨迹，学生本人签核并填写个人验收表。
