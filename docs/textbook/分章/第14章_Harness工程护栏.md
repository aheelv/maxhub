# 《人工智能工具应用实践》

## 第 14 章　Harness 工程实践：规则、Hook、子代理与权限

> **所属模块：**模块四 · Harness 与 AI 集成开发环境（重点模块）　|　**学时：**2 课时（讲授 45 分钟 / 实践 45 分钟）　|　**课程主线定位：**把智能体从「能用」管到「可控」——用四道护栏把能力关进可审计的边界里

### 一、本章定位与主线

本章是模块四的工程收束。前几章已经能跑通任务、造出工具，本章解决「谁允许它做什么、出事怎么拦、做了什么怎么查」。章题、模块与学时不变，本次把 MCP 2026-07-28 官方规范的安全原则作为四道护栏的协议层依据，并把导入与案例统一到「可控」这一主线上。

### 二、导入

一个已跑顺的智能体任务，被要求「顺手把结果写回共享目录」。它照做了，还改了两个不该改的文件。事后复盘发现，既没有规则文件说明可写范围，也没有在写入前触发确认，更没有留下可追查的日志。问题不在模型越权「有意」，而在我们没把边界写成机器可执行的约束。

MCP 2026-07-28 官方规范把这件事写得很清楚：工具代表任意代码执行，主机须在调用任何工具前取得用户明确同意；用户对数据访问与操作应保持控制；工具描述除非来自可信服务器，否则应视为不可信输入。本章据此把课程主线落到四道护栏：规则文件、Hook、子代理分工、权限与沙箱，再配上一份可复用的技能。

### 三、学习目标与可检验能力

本章服务于「快速掌握并熟练使用最新 AI 工具、独立解决多类真实问题」的课程总目标，学完应能：

1. 写出一份项目规则文件，明确可读写范围、禁止动作、输出格式与「不确定时如何做」；
2. 说明 Hook 在关键时点自动介入的机制，能为「写入前」「结束前」各设计一条检查；
3. 用子代理拆分任务并说明上下文隔离的作用，避免一个会话既执行又自评；
4. 依据 MCP 官方规范三项安全原则，配置权限、审批与沙箱边界，并逐项说明对应条款；
5. 独立完成「四道护栏」搭建与一次越界拦截演练，产出可审计的规则、日志与技能文件。

### 四、核心知识点与知识递进

1. 规则文件：可读写范围、禁止动作、输出格式、终止条件、不确定时的处置；
2. Hook 钩子：在什么时点触发、能做什么、为什么必须可观测；
3. 子代理分工：角色边界与上下文隔离，避免自我审校；
4. 权限与沙箱：最小权限、审批策略、可写目录白名单、撤销入口；
5. 技能（Skill）结构：SKILL.md 的写法、技能目录层级与复用方式；
6. 连接器与 MCP：接进来的工具最终进入同一张工具清单，须按同一套授权规则管理；
7. MCP 三项安全原则：用户同意与控制、数据隐私、工具安全；工具描述属不可信输入。

#### 案例 14-1　MCP 2026-07-28 规范：工具安全与用户同意　`A 类 · 可核验官方规范`

- **案例背景：**MCP 官方规范安全章节列出三项关键原则：用户同意与控制（明确同意并理解所有数据访问与操作、保留对共享数据与动作的控制、提供清晰的授权 UI）、数据隐私（暴露用户数据前须取得明确同意、不得未经同意转发）、工具安全（工具代表任意代码执行；工具描述与注解除非来自可信服务器否则视为不可信；调用任何工具前须取得明确同意）。
- **适用知识点：**权限与沙箱、审批策略、工具描述不可信、连接器治理
- **来源／使用场景：**https://modelcontextprotocol.io/specification/2026-07-28（官方规范页，图 S16）；扩展机制见 https://modelcontextprotocol.io/extensions/overview（图 S17）。
- **面向真实问题的实践任务：**把三项原则逐条翻译成本章项目的四条可执行护栏，并写出每条护栏的「违反时可观察现象」；说明为什么「工具描述」不能被当作可信指令。

#### 案例 14-2　DeepSeek Harness：规则注入、沙箱与脚手架成本　`A 类 · 可核验公开文档`

### 八、本章实践任务（面向真实问题）

**任务名称：**第 14 次课｜工程护栏与 Hook：给项目装上四道护栏并完成越界拦截

**真实问题情境：**一个能读写文件的智能体任务需要交付给他人复用。你必须用规则、Hook、子代理分工、权限与沙箱四道护栏，把「能做什么」写成机器可执行的约束，并用一次越界写入演练证明护栏确实生效。

**建议时长：**85 分钟（与课程网站已发布的第 14 次课练习资源包一致，≥60 分钟）　|　**完成方式：**单人独立完成，以 WorkBuddy 等工具为主要完成工具；审查视角用独立新会话实现

**主要工具：**WorkBuddy / Harness 类工具（规则文件、Hook、子代理、权限与沙箱、技能、连接器配置、独立新会话）；浏览器核对 MCP 官方规范

**操作步骤：**

1. 打开 MCP 2026-07-28 官方规范页，摘录三项安全原则，写《护栏依据卡》并逐条对应到本项目。
2. 写一份项目规则文件：可读写范围、禁止动作、输出格式、终止条件、不确定时的处置，控制在「最小完备」长度。
3. 设置两条 Hook：「写入前检查可写目录」「结束前核对产物清单」，记录触发时点与检查内容。
4. 用子代理拆分「执行」与「审查」两个角色，确保审查会话不接触执行者的自评结论；写出上下文隔离说明。
5. 配置权限与沙箱：可写目录白名单、需审批动作、撤销入口；完成连接器／MCP 配置验证，确认所有接入工具进入同一张清单并受同一套授权规则约束。
6. 运行一次越界写入演练，保存拦截日志与回滚记录；编写一个「写入前检查」技能（SKILL.md 骨架）。
7. 另开独立新会话以审校员视角只依据规则、日志与产物复核四道护栏，学生本人签核；填写个人验收表并导出。

**成果要求：**

- 《护栏依据卡》（逐条对应 MCP 规范三项原则）
- 项目规则文件、两条 Hook 配置与触发日志
- 《子代理分工与上下文隔离说明》
- 《权限与沙箱配置记录》（含白名单、审批、撤销入口）与连接器／MCP 验证记录
- 《越界拦截日志与回滚记录》、《写入前检查》技能 SKILL.md 骨架
- 独立新会话审校记录、本人签核说明、个人验收表

**配套资源：**课程网站第 14 次课资源包 `资源包_第14次课_工程护栏与Hook.zip`（https://aheelv.github.io/exercises.html）。
