## 一、任务定位与设计立场

本次工作的对象是**一门课程的全部数字空间**，而不是若干个页面的视觉改版。现存空间在数轮建设中累积了课件、教材、练习、案例、术语、下载包等大量高质量内容，但它们是按"生产批次"而非按"教学逻辑"组织起来的：每新增一类成果，就新增一个平级入口。结果是内容越丰富，学生越难回答三个基本问题——**这周学什么、该看哪些材料、做完交到哪里**。

因此本次重构确立三条立场：

1. **以单门课程为根，以课次为唯一组织轴。** 站点实例代表一门课的一次开课轮次；教材章节、课件、教案、大纲单元、日历条目、习题、实践资源包全部以稳定的 `session_no` 对齐到同一个课次。"课次聚合页"是教与学的统一入口。
2. **内容实体化、元数据化、关联化。** 每一份材料都是带 ID、类型、状态、来源、知识点与关联的内容对象，页面只是这些对象的视图。杜绝"一段 HTML 里既有大纲又有教案"这类混排。
3. **与超星学习通互补而非竞合。** 公开站点做"课程内容主数据源"，超星做"教学运行与学情主系统"。凡涉及身份、选课、作答、成绩、签到、讨论、个人通知的能力，站点一律不重复建设。

**范围声明**：本次交付的是**站点地图、栏目与内容模型、对接字段映射、模板配置说明及可复用模板包**，属架构与契约层交付；未改动 `site/` 下任何现网页面，未改动 `site/assets/js/decks/` 下任何课件文件，未推送 GitHub Pages。落地实施按 `01_站点地图.md` 第八节的迁移顺序执行。

## 三、现状信息架构诊断

### 问题 1 · 缺少统一组织轴，15 个栏目平级并列

`site/assets/js/app.js` 的 `NAV` 数组共 11 项：首页、课程介绍、课程大纲、课件中心、练习下载、知识模块、案例展示、术语词典、技术趋势、拓展资源、个人中心。它们之间是**并列关系**，没有层级，也没有一个能回答"第 8 次课要用哪些材料"的聚合点。

与此同时，"第 8 次课"这个概念在四个地方各自存在、互不引用：

| 载体 | 标识方式 | 是否可被其他栏目引用 |
| --- | --- | --- |
| `deck-08.js` | `n: 8` | 否，仅课件页渲染 |
| `syllabus.html` | 第 8 个 `.acc` 手风琴 | 否，HTML 文本 |
| `exercise-meta.json` | 键 `"8"` | 仅在下载页生成卡片 |
| `教材/分章/第08章_*.md` | 文件名序号 | 否，未接入站点 |

**后果**：新增或修改一次课的内容，需要同步改 4 处以上且没有一致性校验；学生需自行在栏目间"拼图"。

### 问题 2 · 大纲与教案混排

`syllabus.html`（40 KB）包含 16 个课次手风琴、78 个 `h4` 环节标题，固定为「背景与来龙去脉 / 核心内容 / 最新技术实践 / 拓展实例 / 技术发展趋势」五段。这些是**教案素材**（讲什么、怎么讲、举什么例），却挂在"教学大纲"名下；而大纲应有的"模块—课次—教学内容—学时—要求"结构反而没有独立字段。教案本身没有独立 URL、没有教学目标/重难点/时间盒/教具/反思字段。

### 问题 3 · 教学日历完全缺位

全站 15 个 HTML 与 4 个公共 JS 中检索「教学日历」「calendar」均为 **0 处**。既无周次视图，也无交付物截止时间视图。学生无法从站点获知"第几周上到哪一次课"。

### 问题 4 · 教材成果未进入站点

上一阶段已交付 16 章可教学教材文本（合订约 12.66 万字）、逐章修改说明（约 5 万字）、24 张可核验真实截图与来源总表，但站点 15 个页面中**没有任何教材入口**，`index.html` 与 `resources.html` 均未引用。高质量成果处于"站外"状态。

### 问题 5 · 习题与实践被降级为"下载列表"

`site/exercises.html` 有 82 KB、209 处下载链接，功能上完整；但它是**文件清单**而非**题目实体列表**。任务单的时长、独立性、使用工具、成果物、100 分量规、关联知识点、教师核验卡等信息存在于 ZIP 内的 Markdown 中，页面与数据层不可检索、不可与课次和知识点关联，也无法作为题库导出给超星。

### 问题 6 · 知识图谱只有"形"，没有"数据"

`site/modules.html` 是 5 个模块的静态说明，`glossary-data.js` 有 103 条术语及 `rel` 互链，但全站**没有知识点实体、没有知识点层级、没有前置/后置/关联关系、没有知识点与资源和题目的关联**。这意味着"知识图谱双向导入导出"目前没有站点侧数据源——这是本方案必须补上的关键一层。

### 问题 7 · 与超星学习通存在实质性功能重复（最高优先级）

`site/server.js` 暴露 20 个 `/api/*`，`site/data/db.json` 含 7 类业务数据：

| 站点自建能力 | 具体端点 / 页面 | 超星侧既有能力 | 处置 |
| --- | --- | --- | --- |
| 注册 / 登录 / 登出 / 教师登录 | `/api/auth/*`、`login.html` | 平台统一身份 | 下线，改跳转 |
| 扫码登录 | `/api/qr/*`、`qr.html` | 学习通 App | 下线 |
| 选课意向登记 | `/api/enrollments/*` | 教务选课 / 平台班级 | 下线 |
| 课程反馈 | `/api/feedback/*` | 问卷、评教、讨论 | 下线，改跳转 |
| 学习统计 | `/api/stats` | 学情统计 | 下线 |
| 个人中心 | `portal.html` | 平台个人空间 | 下线 |
| 通知更新 | `/api/updates/*` | 平台通知 | 仅保留公开公告，不含个人消息 |

两套账号、两套选课、两套反馈会带来数据口径分裂与隐私责任不清。公开站点在 GitHub Pages 上以静态形态运行（已有 `static-mode.js` 降级），本就不适合承载这些能力。

### 问题 8 · URL 与文件命名不利于长期维护

课件播放使用 `lecture.html?n=8` 查询参数；下载文件名为中文且含空格；页面锚点与内容 ID 无统一规则。改为目录式小写 ASCII URL、稳定 ID 与内容 URL 解耦后，才便于外链引用、静态托管与超星资源关联。

## 四、重构目标与原则

| 编号 | 原则 | 可检验标准 |
| --- | --- | --- |
| P1 | 单课程为根 | 全站内容实例的 `course_id` 唯一且一致 |
| P2 | 课次为主轴 | 教材/课件/教案/大纲/日历/习题/实践 7 类内容均以 `session_no` 对齐，`aligned_with` 边齐全 |
| P3 | 三次点击可达 | 任一内容从首页出发不超过 3 次点击 |
| P4 | 一页看全一课 | 课次聚合页可一次取齐该课全部材料与关联知识点 |
| P5 | 一份内容一个原件 | 站点持有原件，超星只引用；不双份维护 |
| P6 | 互补不重复 | 站点不承担身份、选课、作答、成绩、签到、讨论、个人通知 |
| P7 | 可核验、不编造 | A 类素材必带来源/抓取日期/场景；无来源一律「待补充」 |
| P8 | 模板可复用 | 固定结构与按课程可配置项分离；新课程只改配置与内容 |

### 整站骨架（逻辑视图）

```
                        课程（COURSE-ROOT）
                                │
        ┌───────────────┬───────┴───────┬────────────────┐
     课程总览        课次主轴        知识与案例层      系统层
  介绍/大纲/日历   16 × 课次聚合页   图谱/模块/知识点  导航/检索/站点地图
  考核/团队/通知       │            术语/案例/趋势     内容清单/关联图
                        │
        ┌───────┬───────┼───────┬───────┬───────┬───────┐
      教材章节  课件    教案   大纲单元  日历条目  习题   实践包
        └───────┴───────┴───────┴───────┴───────┴───────┘
                        │  kp_ids / covers / assesses
                  知识点（知识图谱）──► 超星学习通
```

三条贯通路径：**按课次**（线性教学路径）、**按知识点**（图谱检索路径）、**按任务**（能力达成路径）。三条路径在课次聚合页汇合。

## 七、明确的边界与保留项

- **未改动现网**：`site/` 下 15 个 HTML、16 个 deck JS、CSS、后端与数据库均未修改；已发布的 GitHub Pages 站点保持原状。
- **未编造数据**：校历具体日期、教务课程编码、超星课程空间 URL、知识点认知维度与语义先修关系、超星开放接口字段名，一律置空并标注「待补充／待核验」。
- **未实施实际同步**：出站 CSV 与入站模板已生成，但未连接任何真实超星账号或接口；接入前须取得校方授权与接口文档。
- **可选项**：如需把教材接入现网、按新 URL 重建页面或推送 GitHub Pages，需另行确认；推送需重新提供凭据。
