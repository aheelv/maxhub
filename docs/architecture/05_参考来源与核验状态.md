## 一、本文档的作用与证据纪律

本次重构交付的是**架构与契约**，其可信度不取决于文字是否流畅，而取决于每一个数字、每一条字段、每一项平台功能是否都能回答"依据从哪来、谁核验过、还缺什么"。本文档即为这三项问题的统一台账。

### 1.1 三类证据

| 类别 | 定义 | 举例 | 使用规则 |
| --- | --- | --- | --- |
| **A · 外部公开可核验** | 可从公开 URL 复查，且留有抓取日期与本地副本 | 超星知识图谱操作手册 PDF、同类课程站点模板 README、MCP 规范页 | 必须记录 `source_url`、`captured_at`、确认的具体结论；**功能确认与字段名确认分开记载** |
| **B · 项目内部实证** | 由脚本遍历本项目真实文件得出，可重跑复现 | 15 个 HTML、16 份课件共 742 页、371 个内容实例、605 条关联边 | 数字一律来自 `course-template/data/` 与 `dist/`，不手填、不估算；`updated_at` 取原件修改时间 |
| **C · 待补充／待核验** | 无可核验来源，或须由校方授权材料确认 | 校历日期、课程编码、超星模板列名、接口字段名、知识点认知维度 | 一律置 `null` 或标注「待补充／待核验」；**不推断、不占位、不编造** |

### 1.2 核验状态词表

定义于 `model/chaoxing-field-mapping.json` 的 `$meta.verification_policy`，并逐字段写入 `datasets[].fields[].verification`：

| 状态 | 含义 | 可否据此写死接口字段 |
| --- | --- | --- |
| `已核验` | 字段名称或功能可在第二节所列公开材料中找到 | 不适用（公开材料仍非本校接口文档） |
| `已核验（功能）` | 平台具备该能力，但具体列名／入口未公开 | 否 |
| `已核验（功能）/ 待核验（接口列名）` | 功能确认存在，模板列名须校方确认 | 否 |
| `待核验` | 须以本校泛雅后台导出的表头、模板或经授权的开放接口文档为准 | 否 |
| `不适用` | 站点内部派生字段或纯说明字段，不参与平台交换 | 否 |

**硬约束**：`tools/validate.py` 强制检查——只要 `integration.chaoxing.api_contract_status` 不是「已获取校方接口文档」，任一 `chaoxing_api_field` 均不得为非 `null` 值。当前 49 个字段中该值为非 `null` 的有 **0 个**。

### 1.3 四条纪律

1. **JSON 优先**：文档与 `course-template/` 下 JSON 出现不一致时，以 JSON 与 `dist/` 构建产物为准，并回改文档（见第七节）。
2. **功能 ≠ 列名**：公开手册能证明"可以设置前置/后置/关联关系"，不能证明"模板里那一列叫什么"。凡后者一律「待核验」。
3. **不把结构样例说成真实运行**：出站 CSV、入站模板、字段映射均为**契约与样例**，未连接任何真实超星账号或接口。
4. **来源留痕**：A 类素材必须同时具备来源 URL、抓取日期、使用场景；任一缺失即降级为 C 类「待补充」，不提供图像、不给出案例结论。

## 七、复核方法与可重复性

### 7.1 一键复核命令

```bash

python architecture-build/build_template_data.py

  --config course-template/config/course.config.example.json \
```

## 八、引用与状态升级规则

### 8.1 文档与代码如何引用来源

1. 文档中引用平台功能时，使用 `SRC-n` 编号并说明"确认的是功能还是列名"。
2. 内容实例的 A 类素材必须同时填写 `source`、`source_url`、`captured_at` 与使用场景；缺一即降级为 C 类。
3. B 类课堂演练数据须在页面显著标注「虚构教学数据，非真实案例」；C 类只列应截界面、建议来源与须记录信息，**不提供图像与结论**。
4. 新增断言或数字时，先改 JSON 与构建器，再改对应文档，最后运行 `crosscheck.py`。

### 8.2 「待核验」升级为「已核验」的流程

| 步骤 | 动作 | 校验 |
| --- | --- | --- |
| 1 | 取得本校模板文件 / 脱敏导出样本 / 经授权的接口文档，登记为新的 `authority_sources` 条目（含 URL 或文件编号、`captured_at`、`confirmed`） | 人工 |
| 2 | 逐列核对后，把对应字段的 `verification` 改为 `已核验`，并在 `evidence` 写明依据 | `validate.py` 检查状态词表 |
| 3 | 若取得正式接口文档，把 `config.integration.chaoxing.api_contract_status` 改为「已获取校方接口文档」 | `validate.py` 解除 `chaoxing_api_field` 的 null 约束 |
| 4 | 填写 `chaoxing_api_field`，重新生成 `dist/export/*.csv` 并做一次脱敏样本端到端演练 | 产出差异报告 |
| 5 | 更新 `03` 文档字段映射表、`05` 本文档状态总账、`04` 文档发布前检查清单第 9 项 | `crosscheck.py` 零错误 |

### 8.3 风险与复核周期

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 外部 URL 变更或下线 | 溯源链断裂 | PDF 与截图已本地留档；每学期开课前复核一次可达性并更新 `captured_at` |
| 平台版本／校方配置差异 | 公开手册功能与本校实际不一致 | 手册仅用于功能级判断；列名、题型、表头一律待校方材料确认 |
| 文档与 JSON 漂移 | 实施时按错误数字开发 | 每次内容变更后强制运行 `validate.py` + `crosscheck.py`；JSON 为准 |
| 未授权数据进入公开站点 | 隐私合规风险 | 入站数据只进 `_restricted/`，静态发布排除清单作为发布前硬性检查 |
| 把契约误读为已上线 | 教学运行事故 | 上线前置条件（`03` 第七节 4 项）未满足前，出站文件只作结构样例 |

**复核周期建议**：每学期开课前一次全面复核；平台升级、校方模板更新、课程课次调整、内容类型或谓词扩展时各触发一次专项复核。

## 九、结论

本次重构的全部结构性结论均可回溯：外部依据为 8 个已复核可达（HTTP 200）的公开来源，其中 SRC-1 另有本地 PDF 与提取文本留档；内部依据为 371 个带原件路径与修改时间的内容实例、605 条关联边及可重跑的构建产物；49 个对接字段逐条标注核验状态，19 个「待核验」与 15 项「待补充」均保留空值并写明解除条件。

**当前可交付且已核验的部分**：站点地图、栏目与内容模型、职责边界与同步契约、通用模板与校验管线。**当前不可交付为"已上线"的部分**：真实超星同步、具体接口字段名、校历日期、知识点语义先修关系与学生数据。二者在本台账中已明确分列，不存在混同。
