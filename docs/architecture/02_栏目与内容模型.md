# 栏目与内容模型 · 元数据 · 内容关联

> 文档性质：信息架构交付物 ②
> 机器可读真值源：`course-template/model/content-types.json`、`relation-vocabulary.json`、`schema/content-instance.schema.json`、`data/content-manifest.json`、`data/graph.json`

---

## 一、栏目与内容类型的分离

本次重构把两个长期混用的概念明确分开：

| 概念 | 定义 | 例子 | 存在形式 |
| --- | --- | --- | --- |
| **栏目（Column）** | 站点导航与 URL 树上的位置，回答"去哪里找" | `/textbook/`、`/sessions/08/plan/` | `model/sitemap.json` 的 35 个节点 |
| **内容类型（Content Type）** | 内容的种类与元数据模板，回答"这是什么" | `textbook-chapter`、`lesson-plan` | `model/content-types.json` 的 17 种类型 |
| **内容实例（Content Instance）** | 一份具体材料，带稳定 ID 与元数据 | `TXT-08`「智能体原理与 MCP 协议」 | `data/content-manifest.json` 的 371 条 |

一个栏目可以容纳多种内容类型（例：课次聚合页含 8 类实例），一个内容实例也可以出现在多个栏目视图中（例：案例既在 `/cases/` 又在课次聚合页的关联卡片里）。**页面不复制内容，只做视图渲染**——这是避免"改一处漏三处"的根本手段。

## 三、公共元数据核心字段（20 项）

所有内容实例共用，定义于 `schema/content-instance.schema.json`。类型专属字段放在 `ext` 中，不污染公共层。

| 字段 | 类型 | 必填 | 语义 | 约束 |
| --- | --- | --- | --- | --- |
| `id` | string | ✓ | 全站唯一稳定 ID | 一经发布不得变更；正则 `^[A-Z0-9][A-Z0-9:._-]*$` |
| `type` | string | ✓ | 内容类型 | 必须命中 17 种类型之一 |
| `title` | string | ✓ | 标题 | 用于导航、检索、面包屑 |
| `course_id` | string | ✓ | 所属课程 | 全站恒为 `AI-TOOLS-APPLY` |
| `session_no` | int\|null | — | 对齐的课次 | **主轴字段**；必须存在于 `sessions.json` |
| `module_id` | string\|null | — | 所属模块 | 形如 `M3` |
| `kp_ids` | string[] | — | 覆盖的知识点 | 每个 ID 必须存在于内容清单 |
| `status` | enum | ✓ | 生命周期状态 | `published / needs-review / draft / 待补充` |
| `version` | string | — | 版本 | 语义化版本，供差异报告 |
| `updated_at` | string\|null | — | 更新日期 | 取自原件文件修改时间，不手工填写 |
| `owner` | string | — | 责任方 | 默认「课程组」 |
| `source` | string\|null | — | 项目内原件路径或来源说明 | **A 类素材必填** |
| `source_url` | string\|null | — | 外部可核验 URL | A 类外部材料必填 |
| `captured_at` | string\|null | — | 抓取日期 | A 类外部材料必填 |
| `evidence_level` | enum\|null | — | 素材分级 | `A / B / C / null` |
| `visibility` | enum | ✓ | 可见范围 | `public / campus / teacher / internal` |
| `files` | object[] | — | 关联文件 | `{path, format, bytes}`，路径须真实存在 |
| `tags` | string[] | — | 标签 | 用于筛选与检索 |
| `url` | string\|null | — | 站内规范 URL | 全站唯一；可为 null（尚未上线） |
| `ext` | object | ✓ | 类型专属字段 | 键集合见类型字典 |

**校验**：`tools/validate.py` 对 371 条实例逐条执行类型检查、枚举检查、A 类来源检查、文件存在性检查、知识点引用检查与 URL 唯一性检查，共 2,805 次断言零错误。

## 四、类型专属字段（`ext`）重点说明

### 4.1 `lesson-plan` 教案

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `lecture_minutes` / `practice_minutes` / `total_minutes` | int | 45 / 45 / 90，与课程配置一致 |
| `objectives` | string[]\|null | 教学目标；现状为空，标注待补充 |
| `key_difficult` | string\|null | 重难点；待补充 |
| `teaching_aids` | string[]\|null | 教具与工具；待补充 |
| `segments` | object[] | 五环节：背景与来龙去脉 / 核心内容 / 最新技术实践 / 拓展实例 / 技术发展趋势；每环节含 `name / content / minutes / status` |
| `review_status` | string | 明确列出待教师补齐的项 |

> 现状 16 份教案已由 `site/syllabus.html` 手风琴抽出五环节正文，但**分钟级时间分配、目标、重难点、教具、课后反思均无来源，一律标注「待补充」，不编造**。

### 4.2 `calendar-entry` 教学日历条目

`week_no / date / weekday / date_rule / hours / delivery_mode / location / due / deliverable`。其中 `date`、`weekday`、`delivery_mode`、`location`、`due` 全为 `null`，`date_rule` 写明「第 N 教学周；具体日期、星期、节次、地点须由教务校历与课表注入」。**站点不推断校历**。

### 4.3 `exercise` 习题 / 综合任务单

`duration_minutes`（70—85）、`independent`（true）、`mode`（单人独立完成）、`tools`、`question`、`theme`、`deliverables`、`rubric_total`（100）、`teacher_key`。这些字段此前只存在于 ZIP 内的 Markdown，本次升级为可检索、可导出的一级元数据。

### 4.4 `practice-kit` 实践资源包

`file_count`、`files[]`（真实文件名清单）、`minutes`。保证下载通道不出现孤儿文件，也便于超星侧以附件外链引用。

### 4.5 `knowledge-point` 知识点

| 字段 | 说明 | 与超星对应 |
| --- | --- | --- |
| `level` / `parent_id` | 1=模块、2=课次下知识点 | 同级 / 子级知识点 |
| `tag` | 标签 | 属性编辑 → 标签 |
| `teaching_objective` | 教学目标（待补充） | 属性编辑 → 教学目标 |
| `cognitive_dimension` | 认知维度（待补充） | 属性编辑 → 认知维度 |
| `category` | 知识点分类（待补充） | 属性编辑 → 知识点分类 |
| `review_status` | 需教师核定的项 | — |

86 个知识点由 16 份课件 `points[]` 原样抽取，**不含语义推断**。术语与知识点按名称包含关系做确定性匹配生成 `defines` 边，并标注"需教师复核"。

### 4.6 `case` 案例

`source_note`、`background`、`applicable_kp_ids`、`practice_task`、`review_status`。现有 8 个案例均有出处标注，但**背景、适用知识点、面向真实问题的实践任务三项在站点侧尚无结构化字段**，已逐条标注待补充；教材文本中已有的案例四要素可作为回填来源。

### 4.7 `asset` 素材

`chapter / scene / kind / capture_status`。24 张 A 类真实界面截图均带来源 URL、抓取日期、章节与使用场景，来自 `textbook-build/screenshot_manifest.json`。

### 4.8 `session` 课次聚合页

`hours / slides / summary / points[] / lecture_minutes / practice_minutes`，另在 `sessions.json` 中保存 8 类内容的 ID 指针与 `prev / next`，供渲染"一页看全一课"。

## 五、素材分级与状态词表

| 等级 | 含义 | 必备字段 | 呈现要求 |
| --- | --- | --- | --- |
| **A · 可核验** | 真实官方页面截图、带出处的真实案例与数据 | `source` + `source_url` + `captured_at` + 使用场景 | 展示来源链接与抓取日期 |
| **B · 课堂演练** | 明确标注的虚构教学数据，非真实案例 | `evidence_level=B` + 显著标注 | 页面显著标注「虚构教学数据，非真实案例」 |
| **C · 待补充** | 尚无可核验截图或案例 | 只列应截界面、建议来源、须记录信息 | **不提供图像、不编造案例结论** |

当前本课程 A 类素材 24 张截图 + 8 个带出处案例；B 类与 C 类在教材文本中已有分级，接入站点时沿用同一词表。

状态机：`draft → needs-review → published`；资料不足直接置「待补充」，不进入公开检索索引（当前 371 实例中 355 条进入 `search-index.json`）。

## 六、内容关联模型

### 6.1 关联词表（14 种有向谓词）

| 谓词 | 名称 | 典型起点 → 终点 | 超星对应 |
| --- | --- | --- | --- |
| `belongs_to` | 归属 | 模块/课次/知识点 → 课程/模块 | — |
| `aligned_with` | **课次对齐** | 7 类内容 → 课次 | 章节任务点关联知识点 |
| `scheduled_as` | 排期 | 课次 → 日历条目 | 教学日历 |
| `covers` | 覆盖知识点 | 课次/教材/课件 → 知识点 | 资源关联知识点 |
| `prerequisite_of` | 前置依赖 | 知识点 → 知识点 | 前置（须教师核定） |
| `next` | 教学顺序后继 | 课次/知识点 → 课次/知识点 | 后置（需复核） |
| `related_to` | 关联 | 知识点/术语/案例互链 | 关联 |
| `assesses` | 考核 | 习题 → 知识点 | 题目关联知识点 / 按知识点抽题 |
| `uses` | 使用素材或工具 | 习题/教案 → 素材/资源包 | 资源关联 |
| `illustrates` | 案例佐证 | 案例 → 知识点/课次 | 资源关联知识点 |
| `defines` | 术语定义 | 术语 → 知识点 | 知识点别名 / 标签 |
| `evidence_for` | 趋势证据 | 案例/数据 → 拓展阅读 | — |
| `supersedes` | 版本替代 | 任意 → 任意 | — |
| `mirrors` | 同内容多载体 | 网页课件 ↔ PPTX | — |

**纪律**：语义先修关系（`prerequisite_of`）不得由课次顺序自动推断；`next` 只表示讲授先后。当前图谱中 `prerequisite_of` 边数为 **0**，并在知识点 CSV 导出中把前置/后置/关联三列留空，附说明「须教师核定」。

| 约束 | 规定 |
| --- | --- |
| 允许范围 | 仅 `related_to` 谓词可出现外部引用；其他谓词的边端点必须解析到内容实例 |
| 呈现 | 外部引用不进入公开导航、不进入知识图谱导出、不生成详情页 |
| 校验 | `tools/validate.py` 与 `architecture-build/crosscheck.py` 均检查标注完整性；未标注即报错 |
| 解除条件 | 教师补齐术语定义后，由构建器重新解析为稳定 ID，`ext_ref` 计数归零 |

`graph.json` 的 `external_references` 节点记录条数、策略与未定义术语清单，便于逐项跟进。**不为凑齐端点而虚构术语条目**。

## 八、内容治理

1. **稳定 ID**：ID 与 URL 解耦；改名只改 `title`/`slug`，旧 URL 做 301，不出死链。
2. **单一原件**：每份内容只有一个 `source`；网页课件与 PPTX 用 `mirrors` 表达同内容多载体，不重复写正文。
3. **版本留痕**：`version` + `supersedes` 保留旧版，但旧版不进导航、不进检索、不进导出。
4. **待补充显式化**：`status=待补充` 的实例不进入检索索引与公开导出；页面以占位卡显示"应截界面 / 建议来源 / 须记录信息"，不提供图像或结论。
5. **审核责任**：`lesson-plan`、`knowledge-point` 默认 `needs-review`，须教师核定认知维度、教学目标、语义前后置关系后方可 `published`。
6. **一致性校验**：任何内容变更后必须运行 `tools/validate.py`；关联边端点必须能解析到内容实例。
