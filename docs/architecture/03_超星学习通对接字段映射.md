## 一、互补定位与单一权威源原则

### 1.1 两系统各自的角色

| | 课程站点 | 超星学习通 / 泛雅平台 |
| --- | --- | --- |
| **定位** | 课程**内容主数据源**（Content Master） | 教学**运行与学情主系统**（System of Record） |
| **主要对象** | 教材、课件、大纲、日历、教案、习题、实践包、知识点、案例、术语、公开素材 | 身份、班级、选课、作业/考试作答、成绩、签到、讨论、通知、学情统计 |
| **形态** | 公开、静态、可外链、无登录态 | 校方授权、登录后使用、承载个人数据 |
| **权威范围** | 内容正文、知识点定义与关系、资源原件 | 学生身份与选课、所有学习行为与成绩、知识点掌握度 |
| **不做的事** | 不采集作答、不算成绩、不存学生个人信息、不发个人通知 | 不改写课程正文、不产生教材/课件原件 |

**单一权威源（SSOT）规则**：每一类数据只能有一个权威源。另一侧的同类数据要么是引用，要么是只读副本，且副本不回写。这条规则直接决定冲突处理方向，也直接消除"两边都改、最后不知道以谁为准"的常见问题。

### 1.2 为什么是"互补"而不是"集成"

超星泛雅平台公开说明的功能覆盖课前、课中、课后全过程：作业、考试、学习提醒、难点答疑、资源推荐、智能出题，以及课程建设、资源管理、教学互动与数据分析（来源 SRC-2）。这些能力站点若自建，只会形成第二套账号、第二套反馈、第二套统计。因此本方案让站点**退回内容侧**，把教学资源以引用/模板方式供给超星，把学情以聚合脱敏方式回流到内容改进，形成闭环但无重叠。

## 二、职责边界矩阵

| 能力 | 站点职责 | 超星职责 | 重复风险 | 裁决规则 |
| --- | --- | --- | --- | --- |
| 课程介绍 / 大纲 / 教材 / 课件 / 案例 / 术语 / 公开资源 | **唯一权威源**，生产与发布 | 引用外链或上传副本（副本不回写） | 低 | 一份内容一个原件 |
| 教学日历（周次与交付物） | 结构权威源 | 具体日期、提醒、截止的执行方 | 中 | 站点不推断日期；日期以教务校历 / 超星设置为准 |
| 教案 / 教师备课 | 教师可见，面向教学设计 | 不承载 | 无 | 教案不导出为学生学习对象 |
| 知识图谱 | 知识点、关系、属性、资源关联的**权威源** | 图谱展示、按知识点组卷、掌握度计算 | 中（易双份维护） | 站点导出、超星消费；超星侧人工增补只进差异报告，不自动回写 |
| 题库题目与素材 | 题目正文、附件、量规的**权威源** | 在线作答、判分、组卷、成绩记录 | 中 | 站点不采集作答；超星不改写题目正文 |
| **学生身份 / 选课 / 登录** | **不承载，仅提供跳转出口** | **唯一权威源** | **高（现状已有重复）** | 下线站点注册、登录、扫码登录、选课登记、个人中心 |
| **学情 / 成绩 / 签到 / 讨论 / 通知** | **不采集、不存储个人级数据** | **唯一权威源与唯一执行方** | **高（现状已有重复）** | 站点只接收聚合、脱敏指标用于内容改进 |
| 课程反馈 / 问卷 | 不自建反馈库 | 问卷、评教与互动 | 高（现状已有重复） | 站点反馈入口改为跳转超星 |
| 公开资源下载通道 | 唯一入口（按课次打包） | 以资源外链方式引用 | 低 | 任一入口都落到同一份原件 |

### 2.1 功能去重处置清单（针对现状）

现状 `site/server.js` 有 20 个 `/api/*`，`site/data/db.json` 有 7 类业务数据。逐项处置如下：

| 现状能力 | 端点 / 页面 | 处置动作 |
| --- | --- | --- |
| 注册、登录、登出、教师登录 | `/api/auth/register` `/login` `/logout` `/teacher`；`login.html` | **删除页面与端点**，导航改为「前往超星学习通」 |
| 扫码登录 | `/api/qr/create` `/status` `/confirm` `/consume`；`qr.html` | **删除** |
| 选课意向 | `/api/enrollments` GET/POST/DELETE | **删除**，改链接到教务/超星班级 |
| 课程反馈 | `/api/feedback` GET/POST/DELETE | **删除**，改跳转超星问卷 |
| 学习统计 | `/api/stats`；`portal.html` 图表 | **删除**；站点不展示任何学习统计 |
| 通知更新 | `/api/updates` GET/POST/DELETE | 保留**公开公告**的静态发布（`/announcements/`），移除个人消息与写接口 |
| 个人中心 | `portal.html` | **删除** |
| 后端与数据文件 | `server.js`、`package.json`、`data/db.json` | 静态发布时排除（现有 `prepare_publish.py` 已有安全断言，应继续保持） |

> GitHub Pages 上的静态展示版已用 `static-mode.js` 将 `/api/*` 降级为只读空数据与写操作 403。本方案是把这种"降级"上升为**明确的架构决策**，而不是临时兼容。

## 三、双向数据流总览

| 数据集 | 方向 | 权威源 | 传输方式 | 触发 / 频率 | 幂等键 | 冲突规则 |
| --- | --- | --- | --- | --- | --- | --- |
| `knowledge-graph` 知识图谱 | **出**（主） | 站点 | 超星模板导入 / 大纲·教材智能导入 / xmind 导入 | 内容发布或知识点审核通过后手动；按版本，非实时 | `kp.id` | 站点为权威源并覆盖；超星手工增补进差异报告，不自动回写 |
| `course-structure` 课程结构 | 出 | 站点 | 大纲文档上传 / 章节模板导入 | 学期开课前一次；变更时增量 | `course_id + session.no` | 站点为权威源；超星仅引用与挂任务点 |
| `item-bank` 题库 / 作业 | 出 | 站点 | 题库批量导入模板 / 智能导入 | 按课次 | `exercise.id` | 题目正文权威源为站点；作答与得分权威源为超星 |
| `resource-index` 资源清单 | 出 | 站点 | CSV/JSON → 资料库外链或批量上传 | 按版本 | `content.id` | 站点持有原件，超星只建引用，避免双份维护 |
| `calendar` 教学日历 | 出（可选） | 站点（结构）/ 教务（日期） | 条目导出或教师手工设定 | 学期开课前，学期级 | `calendar.no` | 日期以教务校历为准；冲突时以超星侧教师设置为准并回写差异报告 |
| `student-roster` 学生信息 | **入（受控）** | 超星 / 教务 | 后台导出 CSV/XLSX → 适配层 → `_restricted/` | 学期初及名单变更 | `student_id_hash` | 唯一权威源为超星/教务；站点不得新建或修改身份记录 |
| `learning-analytics` 学情 | **入（聚合）** | 超星 | 学情统计导出 → 聚合 → 内容改进标记 | 每模块结束或按需，模块级 | `kp.id + term + aggregate_level` | 学情唯一权威源为超星；站点只读、不回算成绩、不产生评价结论 |
| `identity-and-notification` 身份与通知 | 仅跳转 | 超星 | 链接跳转；SSO 待核验 | 用户点击，实时 | 不适用 | 站点不得保留并行账号体系 |

**出站 5 类全部只含课程内容，不含任何学生数据**；入站 2 类的模板文件当前只有表头，不含任何学生记录。

## 四、字段映射表

### 标记说明

- `方向`：`out` 站点→超星；`in` 超星→站点；`internal` 站点内部派生；`config` 由配置注入。
- `核验状态`：**已核验**＝字段/功能可在 `05_参考来源与核验状态.md` 所列公开材料中找到；**待核验**＝须以本校泛雅后台导出的表头、模板或经授权的开放接口文档为准；**已核验（功能）/ 待核验（列名）**＝功能确认存在但字段名未公开。
- 所有 `超星接口字段` 当前一律为 `null`。`tools/validate.py` 强制检查：未把 `api_contract_status` 置为「已获取校方接口文档」前，不得写死任何接口字段名。

## 五、同步协议

| 维度 | 规定 |
| --- | --- |
| **触发** | 全部为**教师显式触发**或**按版本/学期发布**，不设实时自动同步；避免内容草稿被误导入 |
| **方向** | 内容类单向出站；学生与学情类单向入站；不做双向写回同一字段 |
| **幂等** | 每类数据集有稳定幂等键（见第三节）；重复导入按 ID 覆盖，不产生重复知识点/题目 |
| **冲突** | 以 SSOT 裁决；非权威侧的人工改动进入**差异报告**，由教师决定采纳或丢弃，不自动回写 |
| **空值** | `null` 与「待补充」字段不导出为占位字符串；防止把"未知"写成"事实" |
| **失败处理** | 单条失败不阻断整批；产出 `sync-report-{timestamp}.json`，列明跳过项、原因与建议动作 |
| **审计** | 每次同步记录：时间、操作人、数据集、版本、条数、幂等键集合、冲突数、差异报告路径；审计日志留在受控区 |
| **版本** | 内容 `version` 随包导出；超星侧保留导入批次号，便于回滚 |
| **传输优先级** | ① 官方模板导入 / 后台导出表（当前可核验、无需接口授权）→ ② 经授权的开放接口（待核验）→ ③ 人工下载 + 适配层转换（兜底） |
| **职责分界** | 适配层只做字段转换与空值处理，**不允许平台字段反向污染站点内容模型** |

## 六、隐私与合规

1. **最小必要**：只导入完成内容改进所必需的聚合指标；姓名不落地，学号仅存加盐哈希。
2. **受控区隔离**：入站数据只写入 `_restricted/`；该目录带 `.gitignore`，并在发布流程中显式排除。
3. **静态发布排除**：发布的静态产物中不得包含 `server.js`、`package.json`、`data/db.json`、`_restricted/` 或任何含个人数据的文件。现有 `prepare_publish.py` 的安全断言应继续保持并扩展。
4. **聚合与脱敏**：个人级明细只在受控区分析，输出一律按知识点 / 课次 / 班级聚合；不呈现个人成绩、排名或可识别信息。
5. **留存**：`retention_days` 由校方规定；当前配置为 `null`，表示未取得规定前不设自动留存策略，由教师按学期清理。
6. **告知与透明**：`/integration/` 页面公开说明与超星的职责边界、同步范围、字段口径与个人数据处理原则。
7. **授权前置**：任何真实数据导入前，须取得教务/平台管理员授权与本校导出表头或接口文档；未取得前仅使用模板与样例结构，不接触真实学生数据。
