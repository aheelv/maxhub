课堂熟悉练习 · 星辰电商智能体认知地图

45 分钟 · 3—4 人一组 · 纸笔即可完成 · 不编程、不装环境、不交系统

这不是上机实验，也不是开发任务。你要做的是：把四个单元见过的名词，放回一家真实感的企业里，连成一张能讲给别人听的地图。

课堂练习 · 第 2 页 · 第 2 / 9 页

练习定位与规则

先把规则讲清楚，避免把认知练习误当成操作练习。

项目说明
用途课堂熟悉与认知巩固：认得出名词、连得上技术、举得出场景、说得清关系
时长45 分钟（正好占用 90 分钟课时的后半段；前半段为分页讲授）
分组3—4 人一组，角色：记录员、连线员、口述员、质疑员（可兼任）
需要的材料本页第 3—5 页背景材料 + 资料包 08 工作表；纸笔或打印件即可
明确不需要电脑编程、软件安装、账号密钥、联网环境、可运行系统、任何代码阅读
成果形式W1—W4 四张填好的工作表 + 一张手绘全景关系图 + 一段 90 秒口述稿
评价方式对照第 9 页与资料包 09 的预期产出示范自评；不打分、不排名、不提交系统
允许（但不要求）用电脑打开本页翻看；全程离线、只用打印材料同样可以完整完成。

课堂练习 · 第 3 页 · 第 3 / 9 页

背景材料 A · 企业与组织

请通读；后面所有任务都以这家企业为唯一背景，不需要额外资料。

维度材料内容
企业星辰电商（课堂虚构）：日用消费品与生鲜线上直营，区域仓配；成立 6 年
规模年交易额约 12 亿元；在售商品约 3.2 万种；日均订单 2.6 万单；客服中心 60 人；日均售后工单约 1800 单
部门与职责客服中心（受理与答复）、商品部（制度与商品价格）、仓储物流（时效与库存）、财务部（退款与对账）、经营分析部（指标口径）、IT 部（系统对接与日志）、法务合规部（红线与审批）
诉求 1售后政策答复口径必须统一，且要能说明依据的是哪一版制度
诉求 2客户常问「我的退款到哪一步了」，需要能查到订单与工单的真实状态
诉求 3退款金额分级管理：不超过 200 元可自动处理，超过 200 元必须人工复核
诉求 4大促后经营分析部要自助问答「本周退款率为什么升高」，口径要与财务报表一致
记录员请把四个诉求抄到工作表 W2 的第一列，后面要逐条连线。

背景材料 C · 事故、岗位与名词清单

任务 3 的风险标注与任务 4 的口述，都从这里取材。

材料一：一次事故的内部复盘（2026-06）

复盘项内容
经过问答助手把「价保 15 天」答成「30 天」，客户据此申请，形成 213 笔超额赔付
直接原因制度在两个月前已改版，但知识库仍在用旧版本
放大原因答案没有标注引用；资料不足时也没有拒答机制；无人复核即对外答复
整改要求资料版本管理 + 答案必须引用 + 超范围拒答 + 金额类动作人工复核 + 全过程留痕

材料二：岗位 JD 摘录（AI 应用运营专员）

项目内容
职责维护业务知识资料；跟踪答错案例；参与效果评测与口径对齐；协助试点上线与复盘
要求能说清 RAG、工具调用、人工复核、评测指标的基本用途；能与业务方沟通需求与风险
明确不要求不要求独立开发；工程实现由技术团队承担

任务总览

四个任务对应四张工作表，一步一步来，不必一次做完。

任务要做什么用到哪份材料填哪张表检验点
任务 1 · 名词归位把 12 个名词放进五层架构，各写一句「用来解决什么」背景 C 材料三 + 导学页第 6 页W1位置对、用途对
任务 2 · 场景连线把 4 个业务诉求连到所需技术，并写「少了会怎样」背景 A 四个诉求 + 背景 BW2技术不堆砌、能说清后果
任务 3 · 流程排序与风险标注把 8 个环节排成一条链，在至少 3 处标出护栏背景 C 材料一 / 材料四W3顺序合理、例外出口存在
任务 4 · 模拟面试口述写 90 秒口述稿并组内轮流讲，质疑员按量表追问背景 A—C 全部W4结论先行、落到业务
额外产出（组内共同完成）：在 W3 背面手绘一张全景关系图，把「业务问题 → 技术 → 风险 → 岗位」画成一条线。

Step 74 分钟全组对照第 9 页与资料包 09 示范答案自评；标出 1 处差异、1 个仍不确定的概念W4 自评栏
Step 82 分钟教师 / 全班抽 2 组口述，用自评量表收口；把 W1—W4 贴入学习档案课堂收口

预期产出清单

  1. W1 名词归位表：12 个名词 + 所属层 + 一句用途。
  2. W2 场景连线表：4 个诉求 + 所需技术 + 「少了会怎样」。
  3. W3 流程排序表：8 环节有序链 + ≥3 处护栏标注 + 一张手绘全景关系图。
  4. W4 口述稿：90 秒、结论先行、至少 1 个星辰电商例子、至少 1 处风险与岗位表述。

预期产出示范与自评量表

先自己做完再看；示范只用于对齐口径，不要求逐字相同。

示范答案（精简版）

表示范要点
W1RAG / 向量检索 / 重排 / 引用与拒答 → 知识与数据层；工具调用 / 工具白名单 / MCP → 能力与模型层（工具接口侧）；Workflow / ReAct / 多智能体 → 编排与协作层；人工复核 / 评测集 → 运行与治理层。用途各一句，如「重排：把最相关的资料排到前面，不是生成答案」。
W2诉求 1 → 知识检索 + 引用 + 版本管理（少了会答成过期政策）；诉求 2 → 工具调用 + 白名单 + 最小权限（少了只能说套话）；诉求 3 → 流程编排 + 人工复核 + 幂等 + 留痕（少了会越权或重复退款）；诉求 4 → 指标口径 + 结构化查询工具 + 引用（少了口径不一、数字对不上）。
W3判断问题类型 → 查现行制度 →（检索不到则拒答 / 转人工）→ 查订单与金额 → 人工复核（金额 > 200 元）→ 执行或提交退款 → 回复客户 → 留痕。护栏至少标在：查制度（版本与权限）、人工复核（资金责任）、回复客户（引用与拒答）。
W4示范开头：「企业不能直接用大模型，主要不是模型不够聪明，而是它不知道企业最新制度、没有查系统的权限、也不能为答错承担业务责任……」；中段举价保事故；结尾落到「所以需要知识检索、引用与拒答、工具调用、人工复核、评测与留痕，这些分别由知识运营、产品、合规等岗位负责」。
