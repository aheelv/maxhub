核心知识 · 五代开发范式

范式越往后越自主，也越难预测；本专题按此顺序推进，不跳步。

代次范式特点对应实现
1Prompt + 规则一次性问答，无状态ChatPromptTemplate | Model | Parser

3Tool / Function Calling调用业务系统，结构化参数@tool + JSON Schema + 白名单
4Workflow / ReAct Agent固定 DAG 或自主多步推理RunnableBranch / AgentExecutor
5Multi-Agent + 工程化角色分工、护栏、评测、可观测Supervisor + LangGraph + AgentOps

为什么用 LangChain 作为核心工具

统一抽象让「换模型不换链」成为可能，也让教学里的每个概念都有可运行的对应物。

概念LangChain 抽象本专题用途
可组合Runnable / LCEL 管道符 |把提示、模型、解析器、检索、工具串成一条链
并行与分支RunnableParallel / RunnableBranch同时取制度与业务数据；按规则分流工单
知识Document / BaseRetriever / TextSplitterRAG 检索与引用定位
工具@tool / JSON Schema / AgentExecutor结构化调用业务系统、ReAct 循环
观测BaseCallbackHandlertrace 采集，生产替换为 LangSmith / Langfuse
版本固定为 langchain 0.3.x / langchain-core 0.3.x；教学主线不使用任何需要密钥的模型服务。

逐步开发 ① · 最小 LCEL 链

提示模板 → 离线脚本模型 → 字符串解析器，三段用管道符组合；这一段是后面所有链的骨架。

unit1/01_minimal_chain.py · 第 1—22 行
# -*- coding: utf-8 -*-
"""单元一 · 最小 LCEL 链：Prompt | Model | Parser，并挂上回调观测。"""
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))
from common.lc import text_model, TraceCallback

from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是星辰电商的售后助手，只依据给定信息作答，语气简洁。"),
    ("human", "用户问题：{question}\n已知信息：{facts}"),
])
model = text_model(["依据已知信息：订单 A100 已签收 3 天，符合 7 日无理由退货条件。"])
parser = StrOutputParser()

# LCEL：用 | 把「提示词 -> 模型 -> 解析」串成一个 Runnable，可直接 invoke / batch / stream
chain = prompt | model | parser

trace = TraceCallback()
期望输出：模型返回固定答复，TraceCallback 记录 chain_start / chain_end 事件。换成真实模型时，只需替换 model 这一段，上下游完全不变。
