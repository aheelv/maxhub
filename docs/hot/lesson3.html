一、方向说明

智能问答是生成式 AI 用户渗透率最高的用途。CNNIC《生成式人工智能应用发展报告（2026）》显示 76.0% 的用户会让生成式 AI 回答问题，AI 综合助手使用次数同比增长超过 100%；QuestMobile 数据显示截至 2026 年 5 月 AI 原生 APP 月活跃用户达 4.99 亿。

对教学而言，「聊天」本身不是可评分成果；可评分的是知识工程：语料清洗、条目结构化、别名与意图覆盖、越界拒答边界、以及用标准评测集量化准确率。这些环节都能在 WorkBuddy 里用文件读写、网页构建与命令执行完整实现。

本课刻意不依赖任何外部大模型 API、连接器或知识库平台：助手页用纯前端实现检索与匹配，评测用本地 CSV 与脚本跑分。这样学生单人、无额外账号、无额度也能 90 分钟完成；资料库 / 外部智能体平台作为选做扩展，并明确标注「未启用」时的等价替代。

二、学习目标

  1. 能把原始 FAQ 语料清洗、去重并结构化为带 id、别名、标签、来源与适用范围的知识条目。
  2. 能设定越界问题的判定规则与兜底话术，避免助手对范围外问题编造答案。
  3. 能用 WorkBuddy 生成一个零依赖、可运行的单文件问答页，显示命中条目、匹配依据与来源。
  4. 能用 20 题标准评测集跑出准确率与拒答率，做错误分析并至少完成一轮修订。

五、一站式流程

阶段从输入到成品
① 输入素材30 条原始 FAQ + 20 条术语表 + 8 类越界规则 + 20 题评测集 + 知识库模板
② 语料层体检与去重 → 规范化问答 → 结构化知识条目 JSON（含别名、标签、来源、适用范围）
③ 边界层越界判定规则 + 兜底话术 + 低置信度处理；明确「不知道就不答」
④ 应用层单文件问答页：输入问题 → 分词/别名匹配 → 命中条目 → 显示答案、匹配依据与来源；越界则拒答

六、逐步操作指导（90 分钟）

步骤 1 · 0–6 分钟

素材核对与语料体检

目标：清点 8 份素材，量化原始语料的问题（重复、错别字、过期、无答案）。

  1. 建立 第3课_问答助手制作包/。
  2. 让 WorkBuddy 用脚本解析 01_FAQ原始语料.csv，统计行数、重复问题、空答案、含明显错别字或过期标记的行。
  3. 输出 01_语料体检报告.md，列明每一类问题的具体行号。

可整段复制的提示词 / 能力输入：

读取「素材/第3课_问答助手/01_FAQ原始语料.csv」。用命令执行能力解析 CSV 并统计：总行数、完全相同的问题数、语义近似的问题对（列出问题文本）、答案为空的行号、含错别字或口语化需规范的行号、含「已停用/过期」标记的行号。输出 01_语料体检报告.md：一张统计表 + 一张问题明细表（行号 / 问题原文 / 问题类型 / 建议处理）。不要修改原始语料文件。
项内容
输入01_FAQ原始语料.csv、素材包
输出01_语料体检报告.md + 素材核对表
WorkBuddy 能力WB-CMD 命令执行与数据处理
替代路径CSV 若含 BOM 或引号异常，让 WorkBuddy 用 Python csv 模块按 UTF-8-SIG 重读并报告，不要手工改文件。
当场自检点统计表 6 项齐全；问题明细每条都有行号与建议处理。
步骤 2 · 6–16 分钟

清洗与规范化

目标：把 30 条原始 FAQ 收敛为不重复、表述统一、答案完整的规范问答集。

  1. 按体检报告合并重复、剔除过期、修正错别字、补全空答案（只能依据已有语料，不得编造新政策）。
  2. 让 WorkBuddy 输出清洗前后的行数对照与合并映射表。
  3. 写入 02_规范问答集.csv（列：qid, question, answer, source_rows, note）。

可整段复制的提示词 / 能力输入：

依据「01_语料体检报告.md」清洗「01_FAQ原始语料.csv」：① 合并语义重复问题，保留信息最完整的答案；② 删除含「已停用/过期」的条目；③ 修正错别字与口语化表述，但不得改变原意；④ 答案为空的条目，若其他行有可合并的信息则合并，否则标记「待补充」，严禁编造课程政策。输出 02_规范问答集.csv，列为 qid,question,answer,source_rows,note；source_rows 记录该条来自原始语料的哪些行号。另输出一张合并映射表（原始行号 → 新 qid）与清洗前后条数对照。
项内容
输入原始语料、体检报告
输出02_规范问答集.csv、清洗映射表（写入体检报告附录）
WorkBuddy 能力WB-FILE 本地文件读写
替代路径信息不足时按提示标注「待补充」并保留，不得虚构答案。
当场自检点每条都有 source_rows；清洗后条数 ≤30；无完全重复问题。
步骤 3 · 16–28 分钟

结构化知识条目

目标：把规范问答升级为带别名、标签、来源、适用范围的知识库 JSON。

  1. 按 05_知识库模板.json 的字段，为每条生成 2—4 个别名（结合 02_术语表.csv）。
  2. 填写 tags、source、scope、updated 字段；答案必须来自规范问答集。
  3. 写入 03_知识库.json，并用脚本校验 JSON 可解析、id 唯一、别名不冲突。

可整段复制的提示词 / 能力输入：

读取「02_规范问答集.csv」、素材「05_知识库模板.json」与「02_术语表.csv」，生成 03_知识库.json。每条字段：id(q01 起)、question、aliases(2—4 个，包含术语表里的同义说法)、answer(逐字取自规范问答集，不得改写)、tags(1—3 个)、source(填 qid 与原始行号)、scope(只能填 课程内容/作业提交/工具使用/平台操作 之一)、updated(填课程日期占位)。硬性要求：answer 不得新增任何政策或数值；id 唯一；不同条目的 aliases 不得重复。生成后用命令执行能力解析 JSON 并输出校验结果：条目数、id 唯一性、别名冲突数、answer 与规范问答集的逐条一致性比对结果。
项内容
输入规范问答集、知识库模板、术语表
输出03_知识库.json + 校验结果
WorkBuddy 能力WB-FILE 本地文件读写
替代路径JSON 解析失败时让 WorkBuddy 用脚本定位出错位置并修正，不要手工猜引号。
当场自检点JSON 可解析；id 唯一；别名冲突 0；answer 与规范问答集逐条一致。
步骤 4 · 28–38 分钟

定义拒答边界

目标：明确哪些问题必须拒答、低置信度如何处理、兜底话术是什么。

  1. 读取 03_越界问题清单.csv，把 8 类规则改写成可执行判定条件（关键词 / 范围 / 置信度阈值）。
  2. 为每类写一句兜底话术，禁止编造答案。
  3. 写入 04_拒答规则.md，并生成一份 rules.json 供网页读取。

可整段复制的提示词 / 能力输入：

读取素材「03_越界问题清单.csv」。把 8 类范围外问题改写为可执行判定规则，每条含：rule_id、判定条件（关键词或问句特征，须可写成简单字符串匹配）、命中后的处理（固定为「拒答」）、兜底话术（一句话，不提供任何猜测答案，并告知可咨询的渠道）、以及一个示例问句。另定义：① 检索无命中时的处理；② 最高匹配得分低于阈值 0.35 时的处理（低置信度拒答）；③ 同时命中多个条目的处理（取最高分，并列时显示 2 条并标注「可能需要人工确认」）。输出 04_拒答规则.md 与 05_规则配置.json（供问答页读取，结构清晰可解析）。
项内容
输入越界问题清单
输出04_拒答规则.md、05_规则配置.json
WorkBuddy 能力WB-FILE 本地文件读写
替代路径规则用简单字符串匹配即可，不要求正则或语义模型；避免引入外部依赖。
当场自检点8 条规则齐全；阈值与并列处理明确；JSON 可解析。
步骤 5 · 38–52 分钟

生成单文件问答助手页

目标：做出一个双击即可用、会显示依据与来源、会拒答的问答页。

  1. 让 WorkBuddy 生成 06_问答助手.html：内嵌知识库、规则与简单中文分词/别名匹配打分逻辑。
  2. 界面要求：输入框、提问按钮、答案卡片、命中条目与匹配得分、来源行号、拒答提示、示例问题快捷按钮。
  3. 在预览面板实际输入 3 个问题（1 个别名问法、1 个越界问题、1 个无命中问题），确认三种分支正确。

可整段复制的提示词 / 能力输入：

生成单文件「06_问答助手.html」，零外部依赖、零网络请求。把 03_知识库.json 与 05_规则配置.json 的内容内嵌为 JS 常量。实现：① 输入问题后，先按 05_规则配置.json 的 8 条规则检测越界，命中即显示对应兜底话术并停止；② 未越界则做匹配打分：对 question 与每个 alias 计算「中文字符二元组重合度 + 关键词命中加权」，取最高分；③ 最高分 < 0.35 时显示低置信度拒答；④ 否则显示答案卡片，同时展示 命中条目 id、匹配得分（保留 2 位）、命中的别名/关键词、source 字段；⑤ 并列最高分时显示 2 条并标注「可能需要人工确认」；⑥ 页面提供 6 个示例问题按钮（含 1 个别名问法、1 个越界问法）；⑦ 页面底部写明「本助手基于本地课堂 FAQ，不连接外部大模型」。要求中文 UTF-8、移动端自适应、无控制台报错。只输出完整 HTML 代码，不要省略片段。
项内容
输入03_知识库.json、05_规则配置.json、04_拒答规则.md
输出06_问答助手.html
WorkBuddy 能力WB-HTML 网页与应用构建、预览
替代路径若评分算法实现过复杂，可退化为「关键词 + 别名精确包含」的整数打分，阈值相应调整并在规则文件中说明，不影响验收。
当场自检点3 种分支（别名命中 / 越界拒答 / 无命中拒答）实际测试均正确；答案卡片显示来源。
步骤 6 · 52–64 分钟

标准评测集跑分

目标：用 20 道题量化准确率与拒答率，而不是凭感觉说「效果不错」。

  1. 读取 04_评测集.csv（16 道应答 + 4 道应拒答）。
  2. 让 WorkBuddy 用与网页完全相同的匹配逻辑写一个 Python 跑分脚本，逐题输出 实际处理 / 是否正确 / 命中 id / 得分。
  3. 计算应答准确率、拒答正确率、总体正确率，写入 07_评测报告.md 与 08_评测结果.csv。

可整段复制的提示词 / 能力输入：

读取素材「04_评测集.csv」与「06_问答助手.html」中的匹配逻辑。用命令执行能力写一个独立 Python 脚本，复现网页的「越界规则 → 匹配打分 → 阈值拒答」三步，对 20 道题逐题跑分，输出 08_评测结果.csv：题号,问题,期望处理(应答/拒答),期望条目id,实际处理,实际条目id,匹配得分,是否正确,错误类型。随后生成 07_评测报告.md：分别统计 16 道应答题的准确率、4 道拒答题的拒答正确率、20 题总体正确率（均给出分子/分母与百分比），并按错误类型归类列出全部错题与可能原因。不得手工填写数字，必须来自脚本输出。
项内容
输入04_评测集.csv、03_知识库.json、05_规则配置.json、问答页逻辑
输出08_评测结果.csv、07_评测报告.md、跑分脚本
WorkBuddy 能力WB-CMD 命令执行与数据处理
替代路径若网页逻辑与脚本难以完全对齐，把匹配逻辑抽成一个共享的 JSON 规则说明，两边都按它实现，并在报告中说明口径。
当场自检点20 行结果齐全；三个比率均由脚本计算；错题有分类与原因。
步骤 7 · 64–76 分钟

错误分析与一轮修订

目标：针对错题补别名或修正规则，重跑评测并给出前后对比。

  1. 按错误类型给出修订方案（补 aliases、调整阈值、增补越界关键词、修正答案来源）。
  2. 修订 03_知识库.json / 05_规则配置.json / 问答页内嵌数据。
  3. 重跑评测，输出「修订前 → 修订后」对比表，写入 07_评测报告.md 附录。

可整段复制的提示词 / 能力输入：
