# 第11—16次课课堂AI综合练习设计（单人独立完成版）

## 一、使用说明

本手册按课程空间 `site.zip` 内第11—16次课课件设计；每课一道综合任务，贯穿一个场景，学生必须使用 WorkBuddy 完成需求拆解、材料核对、内容/代码/图表生成和结果复查。每课配套任务单、数据文件、验收表或模板，文件均在对应课次资源包内。课堂可执行时长：第11课85分钟、第12课80分钟、第13课90分钟、第14课85分钟、第15课100分钟、第16课90分钟；步骤时长逐项相加与课时相同。

### 教师课前准备

1. 每位学生独立下载并解压对应课次ZIP，在自己的 WorkBuddy 工作区使用同一版本材料。CSV以 UTF-8 编码；不得改动标有“固定预期”的测试材料。
2. 确认学生能打开 WorkBuddy；本地文件/代码/图片等入口以课堂实际版本为准。第14课Hook/MCP与第15课云服务/发布功能，须课前确认是否有课堂授权的沙箱或演示环境。
3. 若产品能力未开通，使用任务卡内的“模拟替代”步骤；学生须标明“模拟/未启用”，不得把文字草案说成已真实连接、已触发或已上线。
4. 学生仅用本手册中的虚构数据与演示身份，不上传真实个人信息、正式密钥或无授权业务资料。任何写入/发布/连接动作由学生先看变更清单并人工确认。

### 学生通用执行规程

每位学生独立完成全部操作，不需要组员分工、同伴互评或多人同时操作。把 WorkBuddy 作为执行助手和独立审查者：需要多视角时，在同一账号下按顺序开启多个独立会话/任务，每个会话只承担一个角色；学生本人负责最终核对、决定和提交。每个操作阶段都按以下顺序做并留证：

1. 在 WorkBuddy 新建/打开本课工作区，先上传或打开本课任务单与资源文件；在提示中声明“本课只能使用这些材料”。
2. 发出“先读材料和验收标准，只返回理解、缺项、拟执行步骤和将生成/修改的文件；未经确认先不要写入、连接或发布”的准备提示词。
3. 学生本人按文件清单逐项确认计划后，让 WorkBuddy 一次完成一个工作包；需要复核时开启新的独立 WorkBuddy 会话，只提供原始材料和验收规则，不把前一会话结论透露给审查会话。每步保留输入、产物/工具结果、检查结果和下一步。
4. 逐条运行固定验收用例；用文件字段、算式、测试输出、可见运行页面或新建的 WorkBuddy 独立审查会话作证。学生本人按证据作最后判断。WorkBuddy说“已完成”不等于通过。
5. 把最终文件按 `L课次-个人-成果名称-版本` 命名；未通过、模拟和未知项都要显式标注。

### WorkBuddy通用准备提示词

> 你是我的课堂AI项目助理。我将独立完成本课任务；请只根据我上传的本课任务单和配套资料工作。先输出：①你理解的目标；②输入文件及版本；③必须遵守的限制；④按分钟的操作计划；⑤逐项验收方法；⑥你将生成或修改的文件清单。此轮只做计划，不写文件、不访问网络、不连接服务、不发布。材料不够时列出具体文件名和字段，不得自行补造。

### 每课统一评价及安全规则

- 六课均按该课的100分评价要点评分；所有评分项合计须为100分。
- 如果 WorkBuddy 请求改动超出任务范围、接触个人数据/凭证、访问未授权路径、调用外部服务或公开发布，立即暂停并由学生确认；没有授权则采用模拟方案。
- 发生错误时保留错误版本和可观察记录，不覆盖固定输入/测试预期；先找第一次偏离验收要求的位置，再修正、重跑。
- 过程记录是可观察的提示、文件差异、调用、测试和结果；不要求或保存模型隐式思维链。

# 第15次课｜用AI集成开发环境构建专业应用

## 主题对应

对应课件“用AI集成开发环境构建专业应用”：需求结构化、数据模型、云数据库持久化、认证与数据隔离、文件存储/清理的取舍、Creator插件开发、Sites发布顺序、上线功能六项和安全合规五项验收。

## 题目背景

社团要做“校园活动报名页”。访客浏览开放活动；登录学生报名并查看自己的记录；管理员创建/关闭活动；容量不超限。第一版不收身份证号、不做聊天或排行榜。附件不是首版必须能力，因此你要独立作出“暂不启用文件存储”的有据决策，并写出未来启用时的访问/删除策略，展示设计判断而非盲目堆功能。

**大题：使用 WorkBuddy 将活动报名页从一页立项推进到可运行、可验收的预览/发布版本，完成数据隔离、容量、附件取舍、Creator与线上验收。**

**独立完成规则：**由你一人操作WorkBuddy和课堂授权的沙箱，依次切换虚构admin-demo、student-a、student-b等演示身份并记录证据；无需真实账号持有人、第二名操作者或组员。正式账号和未授权线上服务不得使用。

## 数据准备

资源包包含 `需求卡.txt`、`events.csv`（容量2/5/10，开放与关闭状态）、`L15-acceptance.csv`、`data-model.csv`、`file-storage-decision.csv`、`schema-reference.sql`、`release-checklist.csv`。演示身份只使用 `admin-demo`、`student-a`、`student-b`，不设置真实密码。

首版表逻辑：`events(event_id,title,start_at,capacity,status)`；`registrations(registration_id,event_id,user_id,created_at,status)`。报名记录只绑定认证用户标识，不存学号/手机号。容量校验必须由云端受权限保护逻辑可靠执行，不能只靠前端按钮禁用。SQL是字段示意，不应不经核对直接贴入任何真实生产数据库。

## 操作步骤（100分钟）

1. **0–10分钟｜写一页立项书**：用WorkBuddy产出用户、痛点、最小功能、可测成功判据、不做清单。你本人把每项验收写成“输入—动作—期待结果”，再让WorkBuddy独立检查是否有无关个人信息和不可判定指标。
2. **10–22分钟｜定模型、角色权限和存储决策**：用WorkBuddy读取 `data-model.csv`，你本人确认两表字段/关系及访客、学生、管理员的读写权限；再完成 `file-storage-decision.csv`：首版无附件需求→不启用文件存储、不新增附件字段、不收文件；记录将来若上传文件需“文件存储对象ID而非文件本体入表、按身份授权读取、删除记录时同步删除文件”的生命周期方案。让WorkBuddy开新会话专门检查权限表是否违背最小权限原则，你本人决定是否采纳建议。
3. **22–37分钟｜搭AI IDE最小骨架**：先让WorkBuddy列修改清单，只生成目录、空白活动列表页和README。确认本地运行；之后逐项做公开活动列表、登录状态、报名表单。每次只改一个功能，先展示差异再运行。
4. **37–55分钟｜接云数据库与认证（仅获授权环境）**：使用WorkBuddy云服务/课堂提供的后端建立演示数据表；完成注册/登录/退出或由教师分发的模拟身份。写入一条student-a报名，刷新后核实仍存在；不在前端放服务密钥。缺云服务时交建表/权限草案并标记“模拟/未启用”。
5. **55–70分钟｜跑功能与数据权限验收**：按 `L15-acceptance.csv` 检查：①核心流程可完整走完；②每条验收可判通过/不通过；③标题为空/容量填abc/人数超额等异常有清晰提示而非白屏；④刷新后报名仍存在；⑤取消报名须二次确认；⑥手机窄屏无重叠。再用student-a/student-b分别登录，从接口/云端查询结果验证A不能读取B记录，不能仅以页面隐藏作为证据。
6. **70–80分钟｜Creator与文件存储边界**：评估“报名名额核验”是否值得写成Creator插件。若当前环境有Creator且隔离沙箱授权，可实现输入`capacity/current_count`、输出`allow/deny/reason`的小插件，测试2席位前两次允许、第三次拒绝；否则由你在普通代码实现该纯函数/接口卡并注明“Creator模拟”。本课附件明确决策为不启用；让WorkBuddy在独立会话按对象存储、访问控制、同步删除三项检查你的未来生命周期方案，你本人完成修正。
7. **80–90分钟｜按正确顺序预览/发布**：本地全流程跑通→将密钥/数据库地址外置→清理虚构调试数据→获授权后用WorkBuddy Sites发布→先未登录访问，再用student-a/student-b验证隔离，最后手机/窄屏验证。无发布授权时展示本地预览并标记未上线，不传播真实链接。
8. **90–100分钟｜安全五项个人复核并交付**：逐项检查①密钥不在前端代码/公开仓库；②未登录看不到敏感数据；③你依次切换两个演示身份验证数据隔离；④不收集无关信息且说明用途；⑤测试与线上环境数据隔离。每一项记录验证方法、截图/查询证据、结论和你本人执行的整改动作；失败项列整改动作，不得一律填“通过”。

## WorkBuddy工具使用说明

- 需求提示词：**“只按需求卡生成用户故事、最小范围、不做清单、events/registrations字段、角色访问矩阵和逐条验收用例。先只输出计划，不创建云服务、不发布。确保容量2时第三次报名在受保护的后端逻辑拒绝，A不能看到B的报名。”**
- 代码提示词：**“本轮只实现公开活动列表；读取本项目README，不新增依赖/文件存储/聊天功能。先列拟改文件并等我确认；完成后运行启动检查，输出实际证据。”** 后续按步骤逐项下达数据库、认证、名额与发布任务。
- Creator测试提示词：**“对输入capacity=2、current_count分别为0、1、2设计三条测试，输出allow/deny/reason。不得连接生产服务或实际创建报名。若此会话无Creator，请只交接口卡，标明模拟。”**
- 云服务/发布/访问策略操作前先阅读工具展示的变更和公开范围并由你本人确认；没有许可或适用入口时采用模拟，不能移用其他平台冒充WorkBuddy成果。

## 成果物要求

1. 一页立项书与不做清单；
2. 两表数据模型、角色权限矩阵、文件存储取舍/生命周期卡；
3. 最小运行应用、固定功能验收表与云端持久化证据；
4. student-a/student-b/未登录三类访问测试结果；
5. Creator插件或可复测的接口模拟；
6. 按顺序完成的发布/本地预览证据和安全五项验收表；
7. 所有未通过项由你本人登记整改动作、预计完成时间和复测结果。

## 评价要点（100分）

- 用户需求、最小范围和数据模型：15分；
- 持久化、认证、服务端容量校验和跨账号隔离：25分；
- 六项功能验收和异常输入结果：15分；
- 文件存储决策/生命周期与Creator输入输出验证：10分；
- 发布顺序/预览和证据完整：15分；
- 安全五项、个人信息最小化与授权边界：20分。
