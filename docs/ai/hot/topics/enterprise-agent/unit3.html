四、核心知识：控制流到底归谁

4.1 状态图五要素

要素含义企业场景里的作用
State（共享状态）一次任务全程可见的结构化数据工单号、金额、风险等级、已调用工具、审批结论
Node（节点）一个可独立测试的处理单元分类、取数、风控、财务、答复
Edge（边）节点之间的固定流转取数完成后必走风控
条件边按状态动态选择下一个节点金额 > 500 或存在争议则转人工
Checkpoint在关键节点持久化状态系统重启/人工确认后从断点继续，不重复执行
LangGraph、Dify 等框架的核心抽象就是这五件事。本单元先用纯 Python 实现，你会看到框架并没有魔法：它只是把这些要素标准化、加上持久化、可视化与中断恢复。

4.2 五种范式的控制流对照

范式谁决定下一步典型结构优势代价 / 风险
Workflow（DAG）开发者固定节点 + 条件分支可预测、可审计、易回归路径变化要改代码
ReAct 单智能体模型根据观察Thought → Action → Observation 循环适应信息不全、路径不定可能绕路、死循环、成本波动
Plan-and-Execute先规划再执行计划器拆解 + 执行器逐步完成长任务结构清晰计划过期需重规划
Reflection / 自评模型自我检查生成 → 评审 → 修订提高文案与代码质量评审也会出错，需外部判据
Multi-Agent主管分派 + 角色决策Supervisor / Pipeline / Handoff / Debate多视角交叉校验消息膨胀、责任不清、成本最高

4.3 多智能体四种拓扑

拓扑结构适用主要风险
Supervisor（主管）一个主管分派给多个专业角色并汇总退款审批、跨部门核查主管成为单点瓶颈
Pipeline（流水线）角色按固定顺序交接文档生成、数据加工上游错误被下游放大
Swarm / Handoff角色之间按规则互相转交客服分流、多语言支持转交循环、责任归属不清
Debate（评审）多个角色独立产出后交叉评审高风险决策、合同审阅耗时与成本显著上升

4.4 贯穿案例：为什么退款审批需要多角色

工单 WD-004（退款 899 元 / 有争议）
  triage  → 判定为退款类
  risk    → 金额 > 500 或争议 = high
  finance → 生成退款方案（暂不执行）
  supervisor → interrupt：等待人工确认
  human   → approve / reject
  resume  → 从 checkpoint 继续，写最终结论

注意 finance 只生成方案，不执行退款：写操作被推迟到人工确认之后，这是企业级智能体与演示玩具最关键的分界线。

4.5 工程约束清单

约束不做会怎样本单元实现
步数上限模型反复调用同一工具直至超时MAX_STEPS=5，超出转人工
幂等重试造成重复退款/重复建单工单 idem_key、状态机只执行一次写节点
人工确认 HITL自动对外承诺赔付interrupt 写 checkpoint 并暂停
断点续跑重启后从头再跑，写操作重复resume() 读取 checkpoint 继续
共享状态边界角色互相覆盖字段、消息无限膨胀固定 state 字段 + 只追加 log
成本与延迟多角色把一次请求放大成十次模型调用对照报告统计节点数与人工确认数

4.6 范式选型决策树（复用了单元一的结论，此处落到代码）

  1. 规则可枚举且路径固定？→ Workflow；本单元用 03_workflow.py。
  2. 路径不定但一个角色能完成、风险低？→ ReAct；用 03_react.py。
  3. 需要多个专业判断互相制约，且金额/权限敏感？→ Supervisor + HITL；用 03_multiagent.py。
  4. 不确定时先用 Workflow 打基线：它的输出是后续两种实现的对照标准。

4.7 生产替换点

教学实现生产框架要保持不变的东西
纯 Python 节点函数LangGraph 的 Node / Edge / conditional_edgeState 字段与节点输入输出契约
checkpoint.json框架 Checkpointer（SQLite / Postgres）中断点、恢复语义、幂等键

本地对照脚本CI 里的回归评测流水线同一批样本、同一组指标

五、企业场景实例

场景 1 · 售后退款审批（金额阈值）

WD-004：退款 899 元且客户提出争议

Workflow：条件边直接判定 human_review，路径固定、最快。

ReAct：先查订单、再查风险，高风险时升级人工，多两步但能解释原因。

Multi-Agent：客服分流 → 风控定级 → 财务出方案 → 主管中断 → 人工确认，最慢但职责清晰、审计完整。

选型结论：金额敏感且需跨部门背书，选 Supervisor + HITL。

场景 2 · 采购异常核查（跨系统）

到货数量与采购单不一致，需查 ERP、仓储与发票

输入：一条异常告警；可用资源：ERP 查询、仓储快照、发票 OCR 结果。

做法：Plan-and-Execute 先列核查计划，再逐项取数；任一系统超时则保留已完成结果并转人工，不重新开始。

失败示例：单智能体在三个系统间反复跳转，触发步数上限却没有结论 → 改为先规划 + checkpoint 可避免。

场景 3 · 月结关账协作（顺序 + 复核）

关账需要数据、财务、审计三方依次确认

做法：Pipeline 顺序交接，每个角色把结论写入共享 state；Reflection 角色对照口径表复核一次，发现差异就打回上一节点。

为什么不用 ReAct：顺序是制度规定的，自主跳转反而增加合规风险。

场景 4 · 故障处置（失败与回滚）

客服系统故障时智能体要判断是否切降级方案

约束：只读诊断可自动执行；重启服务、清缓存等写操作必须人工确认。

关键设计：中断时把「已执行的只读检查」写进 checkpoint，人工确认后只执行剩余动作，避免重复调用造成告警风暴。

七、开发模式：控制变量的三实现对照

同一批 12 条工单 + 同一组业务规则 + 同一套输出字段
   ├─ A Workflow     固定 5 节点，规则判定
   ├─ B ReAct        模型式循环，最多 5 步
   └─ C MultiAgent  4 个角色 + 主管 + HITL + checkpoint
   ↓
对照指标：节点/步数 · 人工确认数 · 自动通过数 · 可回归性

本单元刻意让三种实现共用输入与判定口径，只改变「谁决定下一步」。这样才能把差异归因到范式本身，而不是数据或工具不同。这也是单元四离线评测能直接复用的原因。

维度WorkflowReActMulti-Agent
控制流开发者模型主管 + 各角色
可预测性最高中中低
解释性规则即解释有 thought 轨迹有角色日志与审批记录
回归测试易需固定模型输出需固定分派规则
适用金额/权限敏感场景可需加 HITL最合适
不要因为「多智能体更先进」就默认选它。本单元的结论要由对照数据得出：能用 Workflow 说清的业务，就别用循环。

# -*- coding: utf-8 -*-
# 单元三范式 A：固定 Workflow（DAG），步骤确定、可审计、不能自主换路
# 节点：classify -> enrich -> decide -> execute -> reply
import json, os

BASE = os.path.dirname(os.path.abspath(__file__))


def run(ticket, tools=None):
    tools = tools or {"steps": 0}
    state = {"ticket": ticket, "steps": []}
    # 1 classify
    t = ticket["type"]
    state["route"] = "refund" if t in ("退货", "退款", "价保") else "service"
    state["steps"].append("classify")
    # 2 enrich
    state["amount"] = ticket["amount"]
    state["days"] = ticket["days"]
    state["steps"].append("enrich")
    # 3 decide（纯规则，无模型）
    if ticket["missing_info"]:
        state["decision"] = "ask_info"
    elif state["amount"] > 500 or ticket["dispute"]:
        state["decision"] = "human_review"
    elif state["route"] == "refund" and state["days"] <= 7:
        state["decision"] = "auto_approve"
    else:
        state["decision"] = "standard_process"
    state["steps"].append("decide")
    # 4 execute
    state["executed"] = {"decision": state["decision"], "auto": state["decision"] == "auto_approve"}
    state["steps"].append("execute")
    # 5 reply
    state["reply"] = "按固定流程处理：" + state["decision"]
    state["steps"].append("reply")
    tools["steps"] += len(state["steps"])
    return state


if __name__ == "__main__":
    tickets = json.load(open(os.path.join(BASE, "data", "tickets.json"), encoding="utf-8"))
    print(run(tickets[0])["reply"], "| 节点：", run(tickets[0])["steps"])

# -*- coding: utf-8 -*-
# 单元三范式 B：ReAct 单智能体（Thought -> Action -> Observation 循环）
import json, os

BASE = os.path.dirname(os.path.abspath(__file__))
MAX_STEPS = 5


try:
    _TICKETS = {t["ticket_id"]: t for t in json.load(
        open(os.path.join(BASE, "data", "tickets.json"), encoding="utf-8"))}
except FileNotFoundError:
    _TICKETS = {}


def lookup(tid):
    t = _TICKETS.get(tid, {"amount": 499, "days": 5})
    return {"amount": t["amount"], "days": t["days"], "status": "已签收"}


def risk_check(amount):
    return {"level": "high" if amount > 500 else "low"}


def refund(tid, amount):
    return {"refund_id": "RF-" + tid[-3:], "amount": amount}


TOOLS = {"lookup": lookup, "risk_check": risk_check, "refund": refund}


def decide(ticket, history):
    # 教学 MockLLM：按观察结果决定下一步；PROD 换成 Function Calling
    if not history:
        return ("需要订单事实", "lookup", {"tid": ticket["ticket_id"]})
    last = history[-1]
    if last["action"] == "lookup":
        return ("拿到金额，评估风险", "risk_check", {"amount": last["obs"]["amount"]})
    if last["action"] == "risk_check":
        if last["obs"]["level"] == "high":
            return ("高风险转人工", "escalate", {})
        amount = next((h["obs"]["amount"] for h in history if h["action"] == "lookup"), 499)
        return ("风险低，执行退款", "refund",
                {"tid": ticket["ticket_id"], "amount": amount})
    return ("信息充足，结束", "finish", {})


def run(ticket):
    history, steps = [], 0
    for _ in range(MAX_STEPS):
        thought, action, args = decide(ticket, history)
        steps += 1
        if action == "escalate":
            return {"decision": "human_review", "steps": steps, "trace": history, "loop": True}
        if action == "finish":
            return {"decision": "auto_approve", "steps": steps, "trace": history, "loop": True}
        obs = TOOLS[action](**args)
        history.append({"thought": thought, "action": action, "args": args, "obs": obs})
    return {"decision": "max_steps", "steps": steps, "trace": history, "loop": True}


if __name__ == "__main__":
    tickets = json.load(open(os.path.join(BASE, "data", "tickets.json"), encoding="utf-8"))
    r = run(tickets[0])
    print("决策：", r["decision"], "| 步数：", r["steps"], "| 轨迹：", len(r["trace"]))

# -*- coding: utf-8 -*-
# 单元三范式 C：Supervisor 多智能体 + 共享状态 + HITL + checkpoint 断点续跑
import json, os

BASE = os.path.dirname(os.path.abspath(__file__))
CKPT = os.path.join(BASE, "checkpoint.json")
HIGH = 500


def triage(state):
    state["route"] = "refund" if "退款" in state["ticket"]["text"] or "退货" in state["ticket"]["text"] else "service"
    state["log"].append("triage -> " + state["route"])
    return state


def risk(state):
    state["risk"] = "high" if state["ticket"]["amount"] > HIGH or state["ticket"]["dispute"] else "low"
    state["log"].append("risk -> " + state["risk"])
    return state


def finance(state):
    state["proposal"] = {"amount": state["ticket"]["amount"], "action": "退款待审批"}
    state["log"].append("finance -> proposal")
    return state


def supervisor(state):
    if state.get("risk") == "high":
        state["need_human"] = True
        state["log"].append("supervisor -> interrupt(human)")
    else:
        state["need_human"] = False
        state["decision"] = "auto_approve"
        state["log"].append("supervisor -> approve")
    return state


ROLES = [triage, risk, finance, supervisor]


def run(ticket, auto_confirm=False):
    state = {"ticket": ticket, "log": [], "stage": 0}
    for i, role in enumerate(ROLES):
        state = role(state)
        state["stage"] = i + 1
        if role is supervisor and state["need_human"] and not auto_confirm:
            with open(CKPT, "w", encoding="utf-8") as f:
                json.dump(state, f, ensure_ascii=False)
            return {"status": "interrupted", "checkpoint": CKPT, "state": state}
    state["decision"] = state.get("decision", "approved_after_human")
    return {"status": "done", "state": state}


def resume(approve=True):
    if not os.path.exists(CKPT):
        return {"error": "没有待恢复的 checkpoint"}
    state = json.load(open(CKPT, encoding="utf-8"))
    state["log"].append("human -> " + ("approve" if approve else "reject"))
    state["decision"] = "approved_after_human" if approve else "rejected_by_human"
    state["need_human"] = False
    os.remove(CKPT)
    return {"status": "done", "state": state}


if __name__ == "__main__":
    tickets = json.load(open(os.path.join(BASE, "data", "tickets.json"), encoding="utf-8"))
    hi = next(t for t in tickets if t["amount"] > HIGH)
    lo = next(t for t in tickets if t["amount"] <= HIGH and not t["dispute"])

    r = run(hi)

脚本会依次调用三种实现，统计节点/步数、人工确认数与自动通过数，并自动清理残留 checkpoint，保证可重复运行。

# -*- coding: utf-8 -*-
# 单元三：同一批 12 条工单，三种范式定量对照
import json, os
from importlib.util import spec_from_file_location, module_from_spec

BASE = os.path.dirname(os.path.abspath(__file__))


def _load(f, n):
    s = spec_from_file_location(n, os.path.join(BASE, f))
    m = module_from_spec(s)
    s.loader.exec_module(m)
    return m


WF, RE, MA = (_load("03_workflow.py", "wf"), _load("03_react.py", "re"),
              _load("03_multiagent.py", "ma"))


def main():
    tickets = json.load(open(os.path.join(BASE, "data", "tickets.json"), encoding="utf-8"))
    report = {"workflow": {"steps": 0, "human": 0, "auto": 0},
              "react": {"steps": 0, "human": 0, "auto": 0},
              "multiagent": {"steps": 0, "human": 0, "auto": 0}}
    for t in tickets:
        w = WF.run(t)
        report["workflow"]["steps"] += len(w["steps"])
        report["workflow"]["human"] += w["decision"] == "human_review"
        report["workflow"]["auto"] += w["decision"] == "auto_approve"
        r = RE.run(t)
        report["react"]["steps"] += r["steps"]
        report["react"]["human"] += r["decision"] == "human_review"
        report["react"]["auto"] += r["decision"] == "auto_approve"
        m = MA.run(t, auto_confirm=False)
        st = m["state"]
        report["multiagent"]["steps"] += len(st["log"])
        report["multiagent"]["human"] += m["status"] == "interrupted"
        report["multiagent"]["auto"] += m["status"] == "done" and st.get("decision") == "auto_approve"
    # 恢复残留 checkpoint，保证脚本可重复运行
    if os.path.exists(MA.CKPT):
        MA.resume(True)
    with open(os.path.join(BASE, "compare_report.json"), "w", encoding="utf-8") as f:
        json.dump({"tickets": len(tickets), "result": report}, f, ensure_ascii=False, indent=2)
    print("工单数：", len(tickets))
    for k, v in report.items():
        print("%-10s 节点/步数=%3d 人工确认=%2d 自动通过=%2d" %
              (k, v["steps"], v["human"], v["auto"]))
    print("-> compare_report.json")
    return report


if __name__ == "__main__":
    main()

第 6 步 · 5 分钟

写出选型结论

用一页笔记回答：① 哪种范式节点数最少；② 高风险工单在三种实现里分别被怎么处理；③ 如果业务规则明天改了，哪种实现最容易回归验证；④ 本企业售后场景你会选哪一种，为什么。

结论不要写「多智能体最好」。企业级选型的判据是「在满足风控要求的前提下，最可控、最便宜、最容易回归的那一个」。
