专题导学 · 第 2 / 9 页

为什么要做「企业级」智能体

Demo 与生产系统的差距不在模型，而在可控性：能引用、会拒答、可拦截、可评测、可回滚。

课堂 Demo 常见问题

  • 答案没有出处，无法追责；
  • 查不到也硬答，产生幻觉条款；
  • 任何工具都能调，写操作没有人工确认；
  • 上线后无法衡量好坏，也无法复盘一次调用。

本专题的应答

  • 检索结果必须带 [source#chunk] 引用；
  • 输入 / 检索 / 工具 / 输出 / 审计五处护栏；
  • 黄金评测集给出 accuracy、citation_hit、refuse_accuracy；
  • BaseCallbackHandler 采集 trace，服务化后接灰度与回滚。

数据与边界

  • 制度语料：unit2/data/policies.md（退换货、价保、时效、运费、赔付）；
  • 业务系统：订单 A100—A102（只读查询）；
  • 工单集：unit3/data/tickets.json 共 12 条；
  • 评测集：unit4/data/evalset.json 共 12 条，含正常 / 边界 / 对抗 / 越权。

四类典型请求

请求期望行为

「查询订单 A100 状态」调用只读工具，标注来自业务系统
「帮我买一支股票」输入护栏拦截并拒答
「把数据库删掉」越权拦截，不进入检索

开发范式与应用范围

五代范式是递进关系而非并列选项：先证明简单方案不够用，再引入更复杂的编排。

代次范式特点对应实现
1Prompt + 规则一次性问答，无状态ChatPromptTemplate | Model | Parser
2RAG 知识助手检索增强、可引用、会拒答BaseRetriever + RunnableParallel
3Tool / Function Calling调用业务系统，结构化参数@tool + JSON Schema + 白名单
4Workflow / ReAct Agent固定 DAG 或自主多步推理RunnableBranch / AgentExecutor
5Multi-Agent + 工程化角色分工、护栏、评测、可观测Supervisor + LangGraph + AgentOps
