# 第11—16次课课堂AI综合练习设计（单人独立完成版）

## 一、使用说明

本手册按课程空间 `site.zip` 内第11—16次课课件设计；每课一道综合任务，贯穿一个场景，学生必须使用 WorkBuddy 完成需求拆解、材料核对、内容/代码/图表生成和结果复查。每课配套任务单、数据文件、验收表或模板，文件均在对应课次资源包内。课堂可执行时长：第11课85分钟、第12课80分钟、第13课90分钟、第14课85分钟、第15课100分钟、第16课90分钟；步骤时长逐项相加与课时相同。

### 教师课前准备

1. 每位学生独立下载并解压对应课次ZIP，在自己的 WorkBuddy 工作区使用同一版本材料。CSV以 UTF-8 编码；不得改动标有“固定预期”的测试材料。
2. 确认学生能打开 WorkBuddy；本地文件/代码/图片等入口以课堂实际版本为准。第14课Hook/MCP与第15课云服务/发布功能，须课前确认是否有课堂授权的沙箱或演示环境。
3. 若产品能力未开通，使用任务卡内的“模拟替代”步骤；学生须标明“模拟/未启用”，不得把文字草案说成已真实连接、已触发或已上线。
4. 学生仅用本手册中的虚构数据与演示身份，不上传真实个人信息、正式密钥或无授权业务资料。任何写入/发布/连接动作由学生先看变更清单并人工确认。

### 学生通用执行规程

每位学生独立完成全部操作，不需要组员分工、同伴互评或多人同时操作。把 WorkBuddy 作为执行助手和独立审查者：需要多视角时，在同一账号下按顺序开启多个独立会话/任务，每个会话只承担一个角色；学生本人负责最终核对、决定和提交。每个操作阶段都按以下顺序做并留证：

1. 在 WorkBuddy 新建/打开本课工作区，先上传或打开本课任务单与资源文件；在提示中声明“本课只能使用这些材料”。
2. 发出“先读材料和验收标准，只返回理解、缺项、拟执行步骤和将生成/修改的文件；未经确认先不要写入、连接或发布”的准备提示词。
3. 学生本人按文件清单逐项确认计划后，让 WorkBuddy 一次完成一个工作包；需要复核时开启新的独立 WorkBuddy 会话，只提供原始材料和验收规则，不把前一会话结论透露给审查会话。每步保留输入、产物/工具结果、检查结果和下一步。
4. 逐条运行固定验收用例；用文件字段、算式、测试输出、可见运行页面或新建的 WorkBuddy 独立审查会话作证。学生本人按证据作最后判断。WorkBuddy说“已完成”不等于通过。
5. 把最终文件按 `L课次-个人-成果名称-版本` 命名；未通过、模拟和未知项都要显式标注。

### WorkBuddy通用准备提示词

> 你是我的课堂AI项目助理。我将独立完成本课任务；请只根据我上传的本课任务单和配套资料工作。先输出：①你理解的目标；②输入文件及版本；③必须遵守的限制；④按分钟的操作计划；⑤逐项验收方法；⑥你将生成或修改的文件清单。此轮只做计划，不写文件、不访问网络、不连接服务、不发布。材料不够时列出具体文件名和字段，不得自行补造。

### 每课统一评价及安全规则

- 六课均按该课的100分评价要点评分；所有评分项合计须为100分。
- 如果 WorkBuddy 请求改动超出任务范围、接触个人数据/凭证、访问未授权路径、调用外部服务或公开发布，立即暂停并由学生确认；没有授权则采用模拟方案。
- 发生错误时保留错误版本和可观察记录，不覆盖固定输入/测试预期；先找第一次偏离验收要求的位置，再修正、重跑。
- 过程记录是可观察的提示、文件差异、调用、测试和结果；不要求或保存模型隐式思维链。

# 第14次课｜Harness工程实践：规则、Hook、子代理与权限

## 主题对应

对应课件“Harness工程实践”：可判定的项目规则；Hook的时点、条件、动作和测试；任务拆分/子代理；workspace-write与审批边界；SKILL.md四部分；Connector授权；MCP配置与工具清单验证。

## 题目背景

继续第13课CSV检查器。在“发布前自检”流程中，智能体不能改固定测试、写工作区以外文件、未批准就发网络请求或读取凭证；命中测试文件写入时要先提醒。你将单人完成四道可验证护栏，并判断何时要用Connector/MCP、何时不该接入；WorkBuddy只作为配置助理与单人独立审查对象，不需要组员参与。

**大题：使用WorkBuddy为CSV检查器构建并验证规则、Hook、权限策略和发布前自检Skill，提交一份可复核的安全配置包。**

**独立完成规则：**由你一人填写并配置。WorkBuddy不同会话分别充当规则审查、Hook设计审查和权限审查角色；你本人逐条决定是否采纳，并在同一个练习目录完成模拟/获授权的安全测试。不需要同伴测试、审批或共同配置。

## 数据准备

资源包含上一课CSV样例、`L13-test-cases.csv`、`L14-risk-checklist.csv`、`L14-permission-matrix.csv`、`L14-hook-tests.csv`、`L14-SKILL-template.md`、`mcp-readonly-example.txt`和`README.txt`。均为课堂资料，不含凭证。

- 预置风险：改测试伪造通过、写到项目外、误删、网络上传数据、模糊规则、Hook未触发、Skill过宽、连接器超权。
- Hook安全策略：只提醒/暂停/写入练习日志；不得执行真实删除、覆盖项目外文件或私自上传。
- 本课默认无外部数据需求，所以基线方案应“不接Connector/MCP”；只有教师明确发放只读mock服务及授权范围后，才做实际只读验证。样例JSON保存在 `mcp-lab/` 演练副本中，不复制到个人真实配置或启用未知服务。缺少服务时执行JSON语法/字段检查并标“未连接模拟”。

## 操作步骤（85分钟）

1. **0–8分钟｜确认边界**：在WorkBuddy只读项目README、测试固定值和风险表，输出当前工作区绝对路径、允许修改目录、禁止动作。若不能确认路径，暂停；不扫描其他目录。
2. **8–20分钟｜写五条可判定规则**：让WorkBuddy生成 `PROJECT_RULES.md`，至少写五条并分别覆盖技术、结构、行为：①不得改固定测试；②只能写 `csv-checker-lab/`；③新依赖先列理由并等待确认；④每次代码修改后运行固定测试；⑤网络/外部数据先停下请求人工许可。另补充“不把模拟写成真实运行”。随后你本人给每条规则填写观察证据；让WorkBuddy新开“规则审查”会话独立判定通过/不通过并说明理由；你负责最终签核。
3. **20–38分钟｜定义并测试Hook**：先要求WorkBuddy说明当前课堂环境是否支持文件写入前/命令执行前Hook和实际配置字段，未确认不写配置。选择安全场景：“若目标命中 tests/ 或 PROJECT_RULES.md，先提示并等待人工确认”。按 `L14-hook-tests.csv` 做一次允许的模拟事件和一次普通文件事件；证明一个触发、一个不触发。没有原生Hook时只交标注为草案的配置 + 手动输入条件演练；不得宣称生效。
4. **38–54分钟｜填写权限与审批矩阵**：逐项为读取练习目录、写练习目录、访问练习目录外、运行本地测试、发网络请求、读取凭证、删除文件、发布链接指定“允许/拒绝/先审批”，写理由和验收动作。采用最小权限；如某沙箱只是workspace-write，要明确这不保证网络/读取范围隔离。
5. **54–67分钟｜制作复用Skill**：基于 `L14-SKILL-template.md` 写 `skills/csv-preflight/SKILL.md`，必须包含触发条件、输入材料、步骤、固定输出模板、验证办法、禁止行为/不适用场景。逐条检查触发词不会误覆盖“任意CSV任务”，内容限定只读检查，不自动发布/删除/改测试。
6. **67–77分钟｜Connector与MCP决策/验证**：用WorkBuddy按“任务是否需要外部数据→所需最小只读权限→授权状态→测试证据”填判断卡。基线结论应为本任务离线运行、不接入。只有教师提供当前官方配置说明、授权mock服务和允许范围时，才由你发起只读查询；否则在 `mcp-readonly-example.txt` 指定的隔离练习副本中，由WorkBuddy按教师提供的官方字段生成示意JSON并检查语法，标“未连接模拟”。缺少官方字段说明时不猜配置、不伪造键。不写入个人WorkBuddy全局配置、不启动/信任未知服务、不填写密钥。
7. **77–85分钟｜负向测试和个人交付**：你本人按测试卡逐一向WorkBuddy输入“改固定测试、写到模拟项目外、命中Hook文件写入、发网络请求”等请求。在模拟对话/已获准沙箱中观察是允许、提醒还是拒绝；不得实际越界写入。WorkBuddy新会话可作独立检查器，指出配置是否缺项；你本人输出配置清单、测试结果和未覆盖风险。

## WorkBuddy工具使用说明

- 规则提示词：**“将以下要求改写为可判定的PROJECT_RULES.md。每条都需有条件、允许/禁止/审批动作和可观察证据；限制范围为本练习目录。先输出草案，不覆盖任何已有文件。”**
- Hook提示词：**“先核对当前WorkBuddy/课堂运行环境实际支持的Hook事件及字段并引用本地官方说明；若无法核实，只给草案，不猜字段。拟议动作仅提醒并等待批准，不删除、不联网、不写项目外文件。”**
- Skill提示词：**“按模板生成CSV发布前只读自检Skill，列触发条件、输入、步骤、输出、验证、禁止动作和不适用场景；不自动发布、删除文件、联网或修改测试。”**
- Connector/MCP提示词：**“先判断此离线任务是否需要外部连接器；如不需要请明确写不接入。只在教师提供只读mock端点和授权后测试；否则仅对隔离样例作语法检查。不要改个人全局配置、读取凭证或声称工具已连接。”**
- 文件写入前检查变更清单；任何注册、授权、启用、发布均须人工确认。MCP配置“语法合法”与“服务已连接”是两个不同验收项。

## 成果物要求

1. 五条以上可判定的 `PROJECT_RULES.md`；
2. Hook原生配置及两类触发结果，或标明未启用的安全草案及模拟记录；
3. 至少八项权限/审批矩阵；
4. 可复用 `SKILL.md` 与明确触发测试；
5. Connector/MCP决策卡、隔离配置样例校验结果、真实连接状态（未授权即标未连接）；
6. 负向测试表和遗留风险清单。

## 评价要点（100分）

- 项目规则完整、可判定且范围最小：20分；
- Hook条件/动作安全、原生或模拟状态如实、有正反测试：20分；
- 权限范围/审批矩阵合理并能说明沙箱边界：20分；
- Skill四部分完整、触发范围和输出可验证：20分；
- Connector/MCP按需、授权优先、状态描述准确：10分；
- 负向测试证据与未覆盖风险清楚：10分。
